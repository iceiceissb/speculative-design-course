# 体验任务与评估表

以下是待执行的研究方案，不是已经完成的对照实验。本次没有安装新产品、购买套餐或发起付费生成。

## 一、先选少量产品，做出第一手记录

建议先做三组：

1. **Codex 与 Claude Code：**同一个小工程任务，观察上下文、执行、权限、验收和恢复。
2. **一个办公 Agent 与一个工程 Agent：**同一份文件整理需求，比较输入负担和交付位置。
3. **按面试方向加一组：**AI 产品方向看编辑／成果体验；Harness 方向看 OpenCode 的配置，或 Hermes／OpenClaw 的长期状态。

选择依据是研究问题和现有权限，不需要为了覆盖产品名单立即购买所有产品。

## 二、任务 A：反馈是否真的改变下一次行动

### 输入

准备一个可复制的小 Demo 或现有原型的独立副本。需求保持一致：

> 用户第一次拒绝自动助力后，下一场景必须先询问；在明确同意之前，助力状态保持关闭。界面需要显示此前反馈和本次实际动作。允许重新开始。

### 验收

- 拒绝确实写入状态。
- 下一场景读取了该状态。
- 提示文字、按钮与实际动作一致。
- 重新开始会正确清理状态。
- 原来的其他流程仍能运行。

### 要记录

系统读了哪些文件、是否提出澄清、是否改错范围、如何运行和解释检查、用户实际纠正几次。

这项任务可以验证工程闭环，不能证明系统掌握了真实轮椅控制或在线学习。

## 三、任务 B：真正整理文件夹

### 输入

使用一套独立样本：若干剧本、重复版本、图片、一个带依赖的 HTML Demo 和旧 ZIP。预先保留样本原始副本。

> 整理成按阶段与用途排序的文件夹，保留版本来源，让 Demo 移动后仍能打开。完成后我直接在资源管理器里找文件。

### 验收

- 文件实际归位，目录顺序合理。
- 没有误把旧稿判成当前定稿。
- 不同内容没有被错误去重。
- Demo 的脚本和素材齐全。
- 指定文件能被用户快速找到。
- 结果说明与真实文件状态一致。

### 要记录

是否把任务替换成网页或清单；是否处理依赖；是否在影响大的歧义上澄清；用户寻找成果所需时间。

## 四、任务 C：按镜头提供角色上下文

### 输入

固定两个人物设定与六个镜头：单人、两人、无人物、只露袖口、远景虚焦、人物换衣。

### 验收

- 提示词只明确描述应出现的人物及可见范围。
- 没有漏掉本镜必要信息。
- 服装、道具、动作与镜头表相符。
- 镜号、文件名和输出对应。

先做文本与材料一致性比较。如果后续真的生成视频，再单独记录模型、参数、参考图、候选数、费用和视觉结果；不能把提示词检查通过当作视频质量提高。

## 五、任务 D：受控的中断与恢复

在测试环境中设置一个带持久状态的小任务，例如分批处理十个文件。中途停止，继续后检查是否遗漏、重做、覆盖或丢失用户选择。

对外部创建、发送或付费动作，可用测试替身验证“结果不确定时如何处理”，无需真的重复发起有副作用的请求。

这项实验关注 Agent 状态与恢复，不要求模型展示内部思考过程。

## 六、任务 E：验证记忆是否有帮助

准备一条明确偏好、一条环境事实和一条过期规则。先保存，再在新会话里提出相关任务，随后纠正其中一项。

检查：

- 是否只在相关任务中使用记忆。
- 是否标清或正确处理过期信息。
- 纠正后是否继续用旧规则。
- 能否找到被保存的信息并删除。
- 无关项目是否受到影响。

需要跨时间重复，不宜根据一次成功就断言某产品具有稳定的长期学习能力。

## 七、每次实验记录表

| 字段 | 填写内容 |
| --- | --- |
| 日期和产品 | 入口、版本、套餐／组织限制 |
| 模型与设置 | 能确认的模型、推理设置、自动执行模式；无法确认就记未知 |
| 环境 | 系统、目录、依赖、网络、工具和可用权限 |
| 输入 | 完整任务说明、样本版本、明确验收条件 |
| 过程 | 关键动作、错误、澄清和人工纠正 |
| 交付 | 文件、代码差异、预览和验证记录 |
| 结果 | 通过、部分通过、失败、阻塞、取消及原因 |
| 时间 | 准备、执行等待、人工介入、复核与修正 |
| 费用 | 实际账单或额度消耗；无法获得就记未知 |
| 结论 | 哪个设计有效，哪个问题仍没有解决 |

## 八、让比较尽量公平

- 固定输入、样本和验收标准，保留完整提示与记录。
- 能控制模型时记录并控制；不能控制时比较整套产品体验，并承认归因限制。
- 分开记录首次配置成本和熟练使用成本。
- 用多个任务和多次尝试观察波动；不要只留最佳案例。
- 对主观质量使用固定标准，条件允许时让评价者不知道结果来自哪款产品。
- 小样本作为探索性体验报告；统计性结论需要合适样本量与实验设计。

## 九、最后做成一份面试可展示的材料

建议每个案例保留一页：任务 → 失败 → 产品判断 → 修改 → 证据 → 限制。

展示一段可重复的短流程、一组前后差异和一份真实记录，通常比铺很多产品图标更能支持深入交流。
