# 把路走通 v2 · 制作与验证

2026-10-18。接续用户要求“继续精细化，建模精细化，内容也更丰富一点”。D08 v1 原样保留，D09 为独立工程。

使用现有 Unity MCP、Blender MCP 和 create-3d-model 工作流；本轮按 quality-refinement-autoloop 保存基线、近景检查并修整资产。没有安装新插件或调用付费生成，没有修改公共 Skill。

## 模型

24 个导出 FBX，包括角色、四类建筑、基础街景与新增道具。角色的源模型包含 220 个可编辑部件，导出为 6 个网格组、18,274 个面，保持四轮可独立转动。Unity 导入检查的角色尺寸约 1.57 × 1.93 × 1.08 米，前向、坐姿和脚踏关系正常。

修整了面部与衣缝贴合、膝部连接、手指显露、轮胎纹理，以及 FBX 法线与根节点轴向。Blender 渲染见 QA/hero_detail_v2.png，工程源文件为 Blender/sunny_assets_v002.blend。

## 内容

SunnyDistrict 提供三类街区配置，分别有不同的目的地、任务、道路色彩、障碍位置及组合。SunnyWorldLayout 构建场景，SunnyJourney 管理邻里事件、现场照片与记录。六类障碍都有真实碰撞与可走的旁路。

轮椅前向碰撞补充了与车体长度接近的盒体检测，避免脚踏明显穿入障碍；平缓坡面允许继续通过。控制器的坡度上限区分陡坡和修复后的坡面。

物品缩略图由实际模型在独立渲染层生成。动画保留轮组转动，增加行人步态与鸟的移动。静态部件按材质合并，切换街区释放动态网格。编辑器中观测到约 60 fps、307 draw calls；不作为其他硬件的性能承诺。

## 测试

三条完整行程通过 139 项检查，耗时约 227 秒：六类物理阻挡和绕行、实际照片写入、重复提交去重、公告阅读、三种目的地互动、任务顺序、返程坡道、回家、九条反馈历史与跨街区存档。测试照片隔离到 QA/Reports，不覆盖玩家自己的照片。

完整结果：QA/playtest_v2_result.json。Windows 独立版已成功构建，自动移动和三类街景、三种任务界面经过截图检查，日志没有运行错误。构建报告为 QA/build_result.json，运行记录为 QA/standalone_smoke.json，画面为 native_theme 系列 PNG。

收尾修正了反向行驶时的轮组旋转方向，花园围栏在入口处留空，以及任务步骤不满足时的界面提示。最终 Windows 包已通过实际键盘检查：Enter 开始、D 行驶、J 反馈记录、M 城市地图、F12 截图。所有按键仅在已核对路径的游戏窗口获得焦点后发送；四张原生截图经目视复核，运行日志无异常，测试进程正常关闭。结果见 QA/native_keyboard_result.json，画面见 native_*_keyboard.png。

## 限制

当前为三类布局复用的 25 街区单人版本。反馈、核查、维修在游戏内模拟，尚无多人同步或真实政府接口。人物和街景为风格化游戏模型，没有宣称写实人体或工程级轮椅结构。
