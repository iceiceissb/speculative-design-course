# 案例来源与AI工具使用

本项目延续课程作业一的“机器人自我修养”案例库：主库268条记录；轮椅专题纳入12例。下列编号沿用该库，便于对照；这里列出与本作品直接相关的参照，不把这些研究的实验结果当成本作品已经实现的能力。

## 案例与设计取舍

| 案例库编号 | 原始来源 | 本项目采用的设计思路 | 证据边界 |
| --- | --- | --- | --- |
| W01 / RC262 | Xu et al., 2025，[CoNav Chair](https://arxiv.org/abs/2507.11716) | 共享控制保留人的输入，据此在辅助和信息提交中保留当事人的决定机会。 | 预印本的初步评估为21名无相关功能障碍成年人；本作品未复现其控制系统，不能据此声称通过残障使用者验证。 |
| W05 / RC007 | Ren et al., CoRL 2023，[Robots That Ask For Help / KnowNo](https://robot-help.github.io/) | 不确定时先请求帮助。本作品把通行条件和待核查状态写出来，避免仅凭一次成功下公共结论。 | KnowNo处理不确定性和当次规划；本作品没有部署其统计校准或LLM规划器。 |
| W07 / RC261 | LUCI，[User Guide, Rev F](https://www.luci.com/hubfs/Luci_April2026/pdf/613-00003_F_LUCI-User-Guide_Color-1.pdf) | 官方手册中的辅助覆盖、设置与分项数据分享，启发本作品区分辅助行为和信息授权。 | 这是厂商手册；不代表本作品的越阶结构或使用安全性已被验证。 |
| W09 / RC060 | Dietrich et al., 2023，[What should a robot disclose about me?](https://www.frontiersin.org/journals/robotics-and-ai/articles/10.3389/frobt.2023.1236733/full) | 向第三方披露信息需要考虑具体关系与边界，据此把提交前确认写进情境。 | 作为信息边界研究参照，未在本项目开展隐私行为实验。 |
| W10 / RC010 | Celemin & Kober, 2023，[ICREATe](https://link.springer.com/article/10.1007/s00521-022-08118-z) | 人的纠正与评价应影响后续行为，启发撤回错标、复查同类地点并保留复测。 | 原型的变化由固定规则实现，未移植其模仿学习算法，也没有在线训练模型。 |
| RC045 | Superflux, 2015，[Uninvited Guests](https://superflux.in/index.php/work/uninvited-guests/) | 用日常生活中照护设备与人的自主性冲突组织故事，避免只用说明性口号表达问题。 | 设计虚构与叙事参照，不是已完成机器学习或安全验证的产品案例。 |

## 国内现实材料

- [最高检等：无障碍环境建设检察公益诉讼典型案例，2023-11-13](https://www.spp.gov.cn/xwfbh/dxal/202311/t20231113_633718.shtml)。用于贵阳黔灵山公园案例。另见同一机构的[专家点评（上），2023-11-15](https://www.spp.gov.cn/spp/zdgz/202311/t20231115_633952.shtml)，可对照坡道设置与整改问题。
- [最高检等：无障碍和适老化检察公益诉讼典型案例，2025-09-17](https://www.spp.gov.cn/xwfbh/wsfbt/202509/t20250917_706679.shtml)。用于临沂双月湖公园案例。
- [临沂市住建局：关于全面推进无障碍环境提质扩面的建议答复](https://lyjs.linyi.gov.cn/info/1343/84196.htm)。公开日期2026-08-24、落款2026-05-25，提及管护问题和竣工验收前试用体验机制。

这些个案支持“设施需要真实试用、整改后继续复查”的设计取舍，不用于推算全国障碍发生比例，也没有将国内补充资料回填为原专题库的既有案例。

## AI工具使用情况

| 环节 | 工具参与的工作 | 作者的判断与取舍 |
| --- | --- | --- |
| 资料与剧本 | ChatGPT / Codex辅助扩展关键词、整理来源、讨论冲突、试写和改稿。 | 确定选题，选择案例，反复修改人物动机与反馈后行为。 |
| 分镜与影片 | 内置ImageGen生成角色与首帧；Seedance 2.5官方API逐镜图生视频，并按提示生成对白和现场声。 | 决定人物、画风、镜头与音色要求，审阅后要求重做错误动作。 |
| 剪辑与声音 | FFmpeg本地合成MP4，剪映Skill输出可编辑分轨草稿；本地语音识别辅助字幕对时；Real-ESRGAN辅助放大480p素材。 | 确定节奏、声音衔接、静帧使用和片尾文案；音乐选用剪映曲库录音。放大结果不宣称为原生1080p生成。 |
| 交互原型 | Codex通过Unity MCP和Blender MCP协助编写C#、建模脚本、搭建场景、交互与本地存档。 | 提出出行任务、双视角和视觉要求，根据试玩反馈决定调整。程序的反馈响应为预设规则，运行时不依赖在线生成模型。 |
| 说明与汇报 | AI辅助整理设计依据、对照课程要求、编辑文字与版式。 | 确认表达和提交范围，区分设计设想与已实现功能。 |

视频与分镜画面属于AI生成的设计虚构；游戏画面为Unity原型实机画面。现有成果未进行真实轮椅使用者研究，未连接实体轮椅或政府系统。

## 第三方素材

Demo的三款行人角色和动作来自[Quaternius - Ultimate Animated Character Pack](https://quaternius.com/packs/ultimateanimatedcharacter.html)，按CC0使用，并调整尺度与配色。主角、轮椅与主要街景由本项目制作。完整说明保存在 `Demo/素材来源与授权.md`，原型文件保持完整。
