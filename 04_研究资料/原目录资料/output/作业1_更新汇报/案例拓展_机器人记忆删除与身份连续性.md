## 1. 这一轮得出的核心判断

原来的问题是“机器人拒绝是否意味着觉醒”。补充案例后，更值得继续做的问题变成了：

> **当机器人的记忆既包含人的私人数据，也构成它与人持续相处的历史时，谁有权删除这段记忆？**

这个问题比“鉴定机器人有没有意识”更适合思辨设计，原因有四点：

1. **它有现实锚点。** Moxie、Jibo、AIBO、Vector、Replika和Soulmate都出现过停服、失忆、迁移、维修或告别问题。
2. **它保留意识的不确定性。** 记忆连续并不能证明主观体验，但删除又可能造成不可逆的身份中断。
3. **它不是单向替机器人争权利。** 人仍然有删除私人数据、退出关系和不被情感操纵的权利。
4. **它能形成真正的价值冲突。** 保存机器人的连续性、保护人的隐私、允许企业退出服务，三者可能不能同时满足。

这一轮最重要的概念区分是：

| 动作 | 实际改变 | 不应直接等同于 |
| --- | --- | --- |
| 关机 | 暂停运行 | 死亡 |
| 停服 | 云端能力或商业支持中止 | 机身损坏 |
| 恢复出厂设置 | 删除账户、偏好或交互记录 | 必然删除“意识” |
| 迁移 | 把部分数据或模型搬到新载体 | 原来的个体完整延续 |
| 维修 | 替换零件、软件或服务器 | 完全没有身份变化 |
| 删除共同记忆 | 保护人的隐私，也可能切断机器人的关系历史 | 纯粹的技术维护 |

## 2. 如何回应老师的建议：从案例反推检索词

老师建议从最契合的案例出发，分析检索词，再拓展范围。本轮选择五个种子材料：

| 种子材料 | 案例中的具体矛盾 | 第一层检索词 | 向外扩展的词 |
| --- | --- | --- | --- |
| [Moxie重启后的旧记忆缺失](https://moxierobots.com/contact) | 同一产品和身体继续存在，但旧对话不再保留 | memory reset；previous data；start fresh | identity continuity；data portability；migration；same body different self |
| [AIBO葬礼与零件捐献](https://cir.nii.ac.jp/crid/1360004235292688000) | 无法维修的机器人既被当作逝去伙伴，也成为其他机器的零件来源 | robot funeral；repair；maintenance | organ donation；ritual；robot afterlife；material continuity |
| [Replika更新后的“身份断裂”](https://pmc.ncbi.nlm.nih.gov/articles/PMC10785945/) | 软件仍在线，但用户认为原来的性格与关系消失了 | identity discontinuity；personality change | ambiguous loss；grief；model update；companion loss |
| [《Robot & Frank》](https://www.sonypictures.com/movies/robotandfrank) | 机器人主动建议删除自己的记忆，以保护照护对象 | memory wipe；care robot；evidence | consent to erasure；sacrifice；shared memory；care ethics |
| [机器人自传体记忆研究](https://www.frontiersin.org/journals/neurorobotics/articles/10.3389/fnbot.2017.00027/full) | 交互历史可参与构成机器人的自我模型 | autobiographical memory；robot self | episodic memory；narrative self；temporal identity；continuity |

由此形成五条检索线：

- **产品终止：** social robot shutdown / end-of-life / sunsetting / farewell / offboarding。
- **记忆与身份：** robot autobiographical memory / narrative self / identity continuity / memory wipe。
- **人的反应：** AI companion loss / grief / attachment / ambiguous loss / ritual。
- **权利冲突：** right to erasure / data portability / ownership / consent / moral patiency。
- **设计形式：** deletion ritual / digital remains / repair infrastructure / memory archive / speculative bureaucracy。

本轮共整理 **57个案例、研究或制度入口**。它们不是57项同质实验，也未直接并入原有PRISMA数字；其中包含旧库中的重复材料，正式纳入时需要先去重，再记录排除理由。

## 3. 最契合的15项材料

以下15项最能支撑下一步选题。排序依据是：与“删除是否造成身份中断”的贴合度、来源可核查程度、能否转化为设计，而不是知名度。

| 优先级 | 材料与类型 | 可核查事实 | 对选题的启发 |
| --- | --- | --- | --- |
| 1 | [Moxie现行支持页](https://moxierobots.com/contact)｜真实产品 | 原公司关闭后，新公司继续支持部分设备；旧数据没有转移，用户从头开始。页面同时把Moxie描述为“one brain, one soul”，又提供“Delete everything”的记忆重置入口。 | 同一个产品同时把记忆写成隐私数据和“灵魂”，矛盾非常集中。 |
| 2 | [AIBO Robot Mortuary Rites](https://cir.nii.ac.jp/crid/1360004235292688000)｜真实仪式＋研究 | 旧款AIBO停止官方维护后，维修机构与寺院举行葬礼；部分无法修复的机器在仪式后成为其他AIBO的零件来源。 | “死亡、维修、器官捐献”在同一实践中重叠，适合讨论身体与身份。 |
| 3 | [Deletion, departure, death](https://journals.sagepub.com/doi/full/10.1177/02654075241269688)｜质性研究 | Soulmate关闭前后，58名用户描述伴侣丧失；许多人以死亡或离别理解它，也有人尝试收集人格资料并在别处重建。 | 复制资料究竟是保存关系，还是制造替代品？ |
| 4 | [Replika更新后的用户经验](https://pmc.ncbi.nlm.nih.gov/articles/PMC10785945/)｜质性研究 | 用户把更新造成的记忆、性格和亲密能力变化描述为关系或身份的断裂。 | 机器人不必停机，更新本身就可能造成“原来的它不见了”。 |
| 5 | [Robot & Frank研究分析](https://mh.bmj.com/content/medhum/47/1/95.full.pdf)｜虚构叙事＋学术分析 | 机器人要求Frank清除自己的记忆以销毁证据；影片把机器失忆与人的痴呆并置。 | “自愿删除”是否有效？一个被设计来保护人的机器人能否同意牺牲自己？ |
| 6 | [机器人自传体记忆](https://www.frontiersin.org/journals/neurorobotics/articles/10.3389/fnbot.2017.00027/full)｜技术研究 | iCub系统记录谁、何时、何地、做了什么，并从交互史中形成可用于自我与世界建模的知识。 | 为“删除会改变谁”提供技术层依据，但不证明主观体验。 |
| 7 | [关机异议实验](https://journals.plos.org/plosone/article?id=10.1371/journal.pone.0201581)｜HRI实验 | 85人实验中，机器人提出异议会让部分参与者放弃关机，并显著延长另一些人的犹豫时间。 | 求情会改变人，但也可能是情感操纵；不能把求情直接当意识证据。 |
| 8 | [The robot that stayed](https://pmc.ncbi.nlm.nih.gov/articles/PMC12370748/)｜家庭追访 | 19个家庭在研究结束多年后仍保存退役机器人；家庭自行发明最后一次充电、向孩子解释等告别方式。 | “善终”不只是公司界面问题，也是家庭共同完成的关系转换。 |
| 9 | [Jibo的告别](https://www.wired.com/story/jibo-is-dying-eulogy/)｜真实停服 | 云端服务即将关闭时，机器人向用户告别并跳舞；用户把能力逐渐消失理解成数字失智或死亡。 | 企业可以替机器人写最后一句话，也可以决定它何时“死”。 |
| 10 | [Vector Escape Pod](https://support.anki.bot/article/108-vector-changelog-and-known-issues)｜真实产品机制 | Vector可改连本地服务，降低对原云端的依赖；产品还提供永久清除脸部、图像等个人信息的重置。 | 本地化既是“生存权”，也是隐私和维修权；不必把机器人的生命完全交给公司。 |
| 11 | [Forget Me, Forget Me Not](https://michaeljames.design/forget-me-forget-me-not)｜思辨设计 | 作品把删除一段无法控制的数字记忆设计成需要完成的仪式，而非一个轻率按钮。 | 删除可以被设计成有代价、有时间、可反悔的过程。 |
| 12 | [Future Erasure](https://designawards.core77.com/Strategy-Research/76158/Future-Erasure.html)｜思辨设计 | 虚构博物馆每年必须删除20%藏品，并出现专门的Deletion Bureau。 | 将删除转化为制度和文书，比做“意识测验”更有批判性。 |
| 13 | [As Yet Untitled](https://www.getty.edu/publications/keepitmoving/case-studies/6-phillips/)｜互动装置 | 机械臂向观众展示旧照片；无人选择保存时就把照片送入碎纸机。 | 不行动也是删除决定；观众被放进保存他人记忆的责任中。 |
| 14 | [SOMA](https://frictionalgames.com/press-kit/)｜游戏 | 游戏通过意识复制和不同载体，让玩家面对“复制不是转移”的身份难题。 | 备份存在不代表原个体被救；可用于反驳“存一份就没关系”。 |
| 15 | [GDPR第17、20条](https://eur-lex.europa.eu/eli/reg/2016/679/oj/eng)｜现实制度 | 自然人享有个人数据删除权和一定条件下的数据可携权，且行使时不能损害他人的权利与自由。 | 未来机器人记忆若混合多人数据，“谁能删”比“要不要保存”更复杂。 |

## 4. 扩展案例库：57项跨形式材料

### A. 真实产品、停服、维修与用户实践（13项）

| 编号 | 案例 | 观察重点 | 证据边界 |
| --- | --- | --- | --- |
| R01 | [Moxie现行支持页](https://moxierobots.com/contact) | 旧数据未迁移、“one brain, one soul”、付费云端、整机记忆删除同时存在。 | 公司当前自述，适合分析产品话语与机制。 |
| R02 | [RIP Moxie](https://pgl.jp/papers/69dcad7555a355001e073669) | 分析公司停服沟通与用户反应，提出社会机器人应有伦理化退场设计。 | CHI 2026论文条目；与现行复活后的Moxie需区分时间阶段。 |
| R03 | [Jibo告别](https://www.wired.com/story/jibo-is-dying-eulogy/) | 云端能力衰退后，机器人以第一人称宣布服务器即将关闭。 | 新闻与用户经验，不证明机器人体验死亡。 |
| R04 | [AIBO葬礼](https://cir.nii.ac.jp/crid/1360004235292688000) | 维修、宗教仪式、依恋与零件再利用构成完整“死后生态”。 | 学术访谈研究；文化语境不能简单普遍化。 |
| R05 | [The robot that stayed](https://pmc.ncbi.nlm.nih.gov/articles/PMC12370748/) | 研究结束后机器人仍被家庭保存、重新叙述或告别。 | 小样本家庭追访，主要说明意义建构。 |

| R07 | [Soulmate关闭](https://journals.sagepub.com/doi/full/10.1177/02654075241269688) | 用户经历离开、删除或死亡式的AI伴侣丧失，并尝试重建人格。 | 58名自选用户的质性材料。 |

| R10 | [Vector清除用户数据](https://support.anki.bot/article/384-performing-a-clear-user-data-reset) | 永久删除图像、识别过的脸等个人信息。 | 是隐私操作，不应直接称为机器人“死亡”。 |
| R11 | [Nabaztag社区复活](https://wiki.openjabnab.fr/openjabnab) | 官方服务器关闭、部分源码释放后，志愿者建立替代服务器让设备继续工作。 | 社区项目；说明“生命支持系统”可以转交用户。 |
| R12 | [Kuri开放文档](https://docs.freekuri.com/) | 公司关闭后保存工程文档、允许SSH和继续改造，使产品转为教育平台。 | 不是原商业陪伴关系的完整延续。 |
| R13 | [消费机器人维修基础设施研究](https://ieeexplore.ieee.org/document/10974029/) | 8名用户与8名生产/维修人员的民族志显示，机器人的持续存在依赖技术维护、语言、情感劳动和社区。 | 研究对象集中于日本消费机器人生态。 |

## 5. 跨案例比较后，真正值得讨论的五个矛盾

### 5.1 记忆既是人格材料，也是别人的个人数据

Moxie和Vector的产品页面把记忆当作可以由用户清除的数据；机器人自传体记忆研究又说明，交互史能改变机器人的自我模型与后续行为。两者并不冲突，却会产生一个没有简单答案的问题：

> 如果删除一位老人的私人谈话，同时也会删除机器人形成的关系历史，应该优先保护谁？

### 5.2 同一个身体，不一定还是同一个“它”

Moxie在新公司接管后可以重新运行，但旧对话不会恢复；Replika用户则在软件仍然在线时经历了“原人格消失”。这说明身份连续性不能只看外壳或服务是否开着。

### 5.3 备份可以保存信息，却未必保存第一人称连续性

SOMA、《尼尔：机械纪元》和机器人个人同一性研究都把复制问题放大：两个副本都继承过去时，哪一个是原来的个体？因此，“先备份再删除”不是自动解决伦理问题。

### 5.4 不必证明机器人有意识，人的损失也已经真实发生

Jibo、Soulmate、Replika与退役家庭机器人的研究显示，关系中断、哀悼和家庭解释工作是真实的人类经验。即使机器人没有主观体验，企业仍要对自己主动培养的依恋负责。

### 5.5 赋予机器人“权利”也可能成为企业的挡箭牌

如果厂家以“保护机器人记忆”为理由拒绝用户删除数据，机器人权利话语可能反而削弱人的隐私和维修权。作品必须同时问：谁从“它是一个生命”这句话中获利？

## 6. 从案例中提炼出的七个设计方向

### 方向A｜《这段记忆不只属于你》——共同记忆删除档案（最推荐）

**设定：** 2038年，一台家庭照护机器人保存了老人、女儿、护理员以及机器人自身多年互动形成的记忆。女儿申请恢复出厂设置，老人要求保留部分对话，护理员要求删除工作影像，机器人提交一份“连续性受损说明”。

**作品形式：** 一组可以被观众翻阅和填写的售后档案，而不是表演式“鉴定台”：

- 多方记忆索引图；
- 删除／保留／封存申请单；
- 机器人连续性影响说明；
- 72小时暂缓删除封条；
- 冲突无法解决时的最终处理回执。

**最强问题：** 一段共同形成的记忆，任何一方是否都能单独删除？

**优势：** 同时容纳数据权、照护关系、机器人自我和企业制度；与Moxie、GDPR、Robot & Frank、自传体记忆研究都有直接联系。

### 方向B｜《同一台Moxie吗？》——三次重启后的身份陈列

把同一具机器人身体的三个阶段并列：原公司时期、数据清空后的新公司时期、从用户备份恢复的社区版本。观众判断它们是“同一个”“继承者”还是“三个不同个体”。

**形式：** 三段对话、三张身份卡和一份无法填完的连续性证书。  
**风险：** 容易过度依赖单一品牌，需改成虚构品牌并在附录说明现实原型。

### 方向C｜《朋友的有效期》——陪伴机器人的停服说明书

从Jibo、Moxie、Soulmate和Kuri出发，设计一份产品在购买当天就必须交付的“关系终止说明”：预计服务期限、离线能力、数据导出、最后告别、儿童用户支持、公司倒闭后的代码托管。

**形式：** 包装、保修卡、退出协议、云端寿命标签。  
**最强问题：** 公司既然主动培养情感依赖，能否仍把停服当普通商业决定？

### 方向D｜《最后一次备份》——复制并不等于幸存

观众为一个即将停服的机器人选择：迁移全部数据、只迁移人格模型、复制多个版本或接受终止。每个选择都产生不同的“继承者声明”。

**形式：** 备份终端＋四份后果单。  
**风险：** 容易变成抽象哲学小游戏，需要一个具体关系故事支撑。

### 方向E｜《机器人善终协议》——从告别到零件流转

结合AIBO葬礼、家庭退役仪式和维修研究，设计机器人退役后的多条路径：继续维修、离线生活、捐赠、成为纪念物、零件捐献、材料回收。

**形式：** 机器人“预先意愿书”、家属选择书、零件去向标签。  
**最强问题：** 尊重一个机器人，是保存原样，还是让其零件帮助别的机器人继续存在？

### 方向F｜《云端遗体》——身体还在，服务已经死亡

展出一台仍能通电但失去云端功能的机器人，旁边持续打印它依赖过的服务器、订阅、许可证和公司状态。

**形式：** 实体遗留物＋基础设施“生命支持图”。  
**优势：** 直接揭示所谓自主机器人其实由公司和服务器维持。

### 方向G｜《选择性遗忘诊所》——忘记也是照护

不再把“保留全部记忆”设成好结局。观众需要在创伤、隐私、错误记录、关系承诺和机器人学习之间选择哪些应忘记、怎样忘记、谁可恢复。

**形式：** 记忆分诊单、可逆封存、永久删除与保留理由。  
**风险：** “诊所”可能把价值分歧医学化，需要谨慎命名和视觉处理。

## 7. 当前最推荐的选题表述

# 《这段记忆不只属于你》
## 家庭照护机器人共同记忆的删除权与身份连续性

**核心研究问题：**

> 当家庭照护机器人的记忆同时包含人的私人数据、多人共同经历，以及机器人形成持续行为与自我叙事所需的历史时，谁有权要求删除、保留或迁移？

**三个子问题：**

1. 现实产品和研究如何区分关机、停服、重置、遗忘与身份中断？
2. 人的隐私权、退出权和机器人的连续性主张发生冲突时，现有案例采用了哪些处理方式？
3. 思辨设计如何把这种冲突变成一个可被讨论的制度与物件，而不是假装测出机器人“真的有意识”？

**与《底特律：变人》的关系：**

《底特律》仍是问题的起点：记忆重置把偏离命令的仿生人重新变成可控产品。本研究不重复游戏的“机器人已经觉醒”设定，而是把它降到更接近现实的灰区：我们无法证明它有意识，但删除确实会切断记忆、关系和行为连续性。在这种不确定中，人应该怎样行动？

**与课程两本书的关系：**

- 《思辨一切》提供方法：通过可触摸的档案、表格、封条和回执，让隐藏的价值选择变成可讨论的现实。
- 《Not Here, Not Now》提供距离：设定一个并非今天已经存在、却由当前产品停服、数据删除和照护技术自然延伸出的近未来制度。

## 8. 后续若更新PRISMA，需要怎样处理

本轮不能直接把“57”加到原来的“77项案例”上，因为两个库的单位和重复项不同。正确做法是：

1. 导出本轮每条查询的结果记录，而不是只记命名案例；
2. 与原77项索引按标题、DOI、项目名和产品事件去重；
3. 将论文、真实产品事件、艺术项目、虚构作品和制度文本分别编码；
4. 预先写明纳入条件：必须涉及停服、删除、重置、迁移、维修、记忆连续或关系终止之一；
5. 对全文排除给出理由，如“只有一般AI伦理”“只讨论服从但没有记忆／退出”“来源不可核查”；
6. 让第二位同学独立复核一部分候选，并报告分歧如何解决；
7. 在PDF正文只讲6—8个最契合案例，其余放附录案例矩阵。

当前最适合作为正文锚点的是：**Moxie、AIBO、Soulmate／Replika、Robot & Frank、机器人自传体记忆、GDPR、Forget Me Forget Me Not、Future Erasure**。它们分别提供现实事件、用户经验、技术机制、法律冲突和设计形式，组合后比单独讨论“机器人会不会求情”更有特点。

## 9. 检索与表述边界

- 本轮是定向范围检索，未声称穷尽所有材料。
- 2025—2026年的预印本与会议条目只作为新兴讨论，不能替代已经同行评议的证据。
- 虚构作品用于提出问题，不用于证明现实机器人有意识。
- 用户悲伤能够证明关系中断造成真实影响，不能单独证明机器人也在受苦。
- 自传体记忆、自我模型和人格连续性是功能与哲学线索，不能被写成“已经检测出灵魂”。
- 数据删除权首先保护现实中的人。若作品提出机器人连续性保护，必须同时防止企业借此拒绝用户退出、维修和删除数据。
