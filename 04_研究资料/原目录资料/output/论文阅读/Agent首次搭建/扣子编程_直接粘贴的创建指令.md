# 新版扣子编程创建指令

适用于没有旧版低代码工作流入口的情况。打开 https://code.coze.cn/，新建开发任务，把下方“发送内容”整体复制过去。生成后在预览环境试运行，检查真实模型调用。此文件是开发需求，不是可导入的工作流文件，也不代表账号内已经完成配置。

第一版只需要一个两阶段的操作页。逻辑对应原论文的两个核心模块；具体实现可以是平台支持的工作流或服务函数。工作流节点截图不是这个入口一定会提供的产物。

## 发送内容

```text
请实际创建一个可在预览中运行的中文 Bodystorming AI 原型，名叫“场外即兴助手”。主要目标是调试和展示AI业务逻辑，界面保持简单。

必须使用当前项目可用的真实大模型集成，不能用硬编码示例、随机模板或占位返回冒充模型调用。如果集成、权限或额度不可用，请明确报错并告诉我缺什么，不能悄悄改成演示数据。先在项目预览里调试，公开部署或发布由我手动操作。

功能有两个阶段：

阶段A：生成突发事件。
输入两个文本字段：story（剧本）、constraints（实际道具、人数、剩余时间、硬限制、学习目标）。
点击“生成5个事件”，先用一次模型调用忠实提炼故事，再用一次模型调用生成恰好5个事件。第二次调用必须同时接收原文、约束和摘要。
请展示提炼摘要和5个事件。每个事件包含唯一编号、名称、内容、类型、象征性表演入口、设定性质和待确认事项。
事件至少覆盖3种实质不同的变化，遵守课堂资源限制，不提供完整应对方案。全部标为课堂虚构扰动，当前未做领域知识核验，不编造文献和检索来源。
学生点击“选择这个事件”后，把该事件的完整内容传给阶段B，不只传编号。保留原始剧本和constraints。若用户更改剧本或约束，旧的摘要、候选、所选事件、支持结果和提示历史都要清空或明确失效；重新生成候选也要清空旧选择，避免上下文串用。

阶段B：支持表演。
显示并允许查看当前所选事件；输入observation（人工现场观察），显示previous_hints（此前提供或明确拒绝的提示）。
点击“判断是否需要提示”，调用真实模型，传入story、constraints、selected_event完整正文、最新observation和previous_hints。
模型规则：
1. 选中事件正文或观察信息缺失时，要求补充，不自行猜测。
2. 学生仍在产生新动作或讨论，没有求助时，L0，暂不追加提示。
3. 只有沉默或静止但无法确认含义时，待确认，不直接判断卡住。
4. 有明确求助或停滞时，从L1开始，给一个反思问题或注意力提示。
5. 有记录证明L1后仍未推进，或学生明确要求更多方向时，L2，最多给两个方向。
6. 只有明确要求具体起点时才L3，给一个身体/空间/道具行动起点，不给完整剧本。
7. 遵守实际道具和时间限制，不重复已拒绝建议，不假装看到摄像头或听到音频。
8. 当前没有RAG，领域知识标为未经检索核验，不虚构来源。
输出当前理解、观察依据、介入级别、给学生的话、下一步可观察变化、知识状态。

本轮展示的实质提示需要记录到当前会话提示历史，并允许用户纠正和补充“采用/拒绝/尚未展示”。每次请求显式传完整上下文，不能仅靠模型聊天记忆。提供“新开一组/清空”按钮，避免混用不同组历史。

界面需要：剧本和约束输入；生成按钮及加载/错误状态；可选择的5个事件；当前选择；人工观察输入；支持按钮及加载/错误状态；提示历史；一键载入示例；重置；导出本次输入输出为JSON或Markdown。
按钮发起调用时禁用重复提交；失败显示真实错误，不保留上一轮结果冒充新结果。调试日志保留每次请求的输入、输出、时间、错误和可获得的模型信息；不要求展示模型内部思维过程。

内置示例：
story：三名学生扮演火星基地建造员、材料研究员和协调员，使用菌丝材料模块搭建临时休息空间。故事里的3D打印设备正在制造连接件；课堂用纸板象征菌丝模块、绳子象征连接、手电筒象征电力，现场并没有真实打印机。
constraints：只有纸板、绳子、手电筒，剩余3分钟，不增加器材。目标是探索资源受限时的替代建造与协作。
observation示例一：团队停下约40秒，反复讨论恢复供电，有人明确请求一点提示，已经拒绝备用电池方向。
observation示例二：团队已经主动用纸板和绳子探索两种连接方式，有持续的新讨论，没有求助。

请完成后在预览中检查：
- 是否真实调用了模型；
- A是否生成5个相关事件；
- B是否收到所选事件全文和资源限制；
- 将观察从明确求助换成自主探索后，是否能返回L0；
- 只给沉默信息时是否保留不确定性；
- 修改剧本或新开一组后，旧选择和历史是否失效；
- 模型调用失败是否诚实显示错误。

不要把生成需求文档当成完成开发。完成后说明实际实现方式、如何运行、真实执行了哪些检查，以及尚未实现的能力。本版本不接摄像头、不做实时语音、不做知识检索；这些在界面上如实标为“尚未接入”。
```

## 生成以后怎么操作

1. 在预览里点击“载入示例”，再点击“生成5个事件”。
2. 选一个事件，输入明确求助的观察，获取一次提示。
3. 将观察换为自主探索，再次调用，检查是否选择L0。
4. 导出原始输入输出，保存实际日志和界面截图。

如果只有界面但没有真实模型输出，可以继续向扣子编程发送：

```text
请检查两个按钮对应的服务端调用。我要真实的大模型推理，不是示例数据或模拟延迟。展示可核实的调用日志；若当前项目没有模型集成权限，请返回明确错误，不要用固定文本补齐。
```

如果始终忽略选中事件，可以发送：

```text
请检查阶段B的请求体：必须显式传story、constraints、所选事件完整正文、最新observation和previous_hints。把这些业务字段显示在可折叠的调试区，不要只传事件编号，也不要只依赖前端组件状态或模型聊天历史。
```

如果每次都强行给建议，可以发送：

```text
增加一个明确的“暂不介入”控制选项，选中时通过程序分支直接显示继续探索、不新增提示。保留“由模型建议”的选项用于调试，不要声称仅靠提示词能保证每次都正确判断。
```
