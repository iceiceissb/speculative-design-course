# 从内容到成片：多媒体制作工作流

2026-11-14。使用方式：用《不用麻烦她》的已完成链路作为证据，把可迁移的方法提炼出来；新增能力均标明为建议。

## 1. 先明确三种分工

| 参与者 | 主要职责 | 需要交出的东西 |
| --- | --- | --- |
| 人：导演／创作者／委托方 | 选择议题、判断人物动机与观感、确认预算与取舍 | 创作目标、取舍理由、阶段验收意见 |
| Claude／GPT 等通用助手 | 研究与写作、分镜拆解、按镜头整理上下文、调度工具、分析失败与追踪版本 | 可读方案、结构化制作表、任务与修改记录 |
| 生成模型、本地程序、剪辑软件 | 分别完成画面／声音生成，以及时间线、字幕、混音、渲染和导出 | 带来源的媒体资产、可编辑工程、可播放成片 |

通用助手调用外部模型时，视频的生成质量和费用仍由相应模型与服务决定。MCP 连接工具，Skill 说明步骤，项目文件保存状态；三者分别解决接入、操作方法和持续制作的问题。

本项目由人持续提出方向、发现问题、决定取舍，AI 辅助完成大部分代码与制作。现有证据不支持“全程无人干预”的表述。

## 2. 从需求到交付的十二个步骤

| 步骤 | 输入与关键工作 | 输出／交接物 | 进入下一步的条件 |
| --- | --- | --- | --- |
| 0 创作简报 | 明确受众、议题、片长、播放场景、画幅、预算和交付版本 | 一页 brief、约束、验收标准 | 能用一句话说明观众需要理解或感受到什么 |
| 1 内容研究 | 访谈／案例／资料，区分事实、创作设定与观点 | 来源记录、核心矛盾、故事问题 | 具体人物和具体情境能够承载议题 |
| 2 故事与剧本 | 故事梗概、人物目标、阻力、行动、转折、结果；写到可拍的动作与台词 | 带版本的完整剧本、场景表 | 每场都有推进；重要变化能在画面或声音里出现 |
| 3 媒体设计 | 逐场决定画面信息、台词信息、动作信息、画外信息和声音氛围 | 镜头表、声音表、图文清单、粗略时长 | 没有要求一个镜头同时完成太多事情 |
| 4 资产与预演 | 角色外形、衣服、道具、场景布局、声音样本；用分镜图与临时声音连成预演 | 角色／场景／声音基准，带时间的分镜预演 | 人物可辨，片长合理，台词能自然说完，关键空间关系看得懂 |
| 5 生产计划 | 给每镜选择视频生成、静帧、实拍、库存或本地图层；列候选数与费用 | 任务清单、模型与输入模式、预算、优先试片 | 明确哪些任务花钱，哪些复用，哪些需要先试 |
| 6 小批量试片 | 优先测试复杂机械动作、双人对白、人物连续性和跨镜声音 | 代表性候选、失败分类、接受／修改决定 | 主要风险有可行表现方法，再扩大生成 |
| 7 素材生产 | 按确认计划生成视频／声音；下载、命名、记录任务 ID 与用量 | 原始候选、来源、版本、状态、费用账本 | 文件落地可用；未完成和结果不确定的任务可恢复 |
| 8 选片与粗剪 | 根据动作与台词选可用区间，接出完整故事；图文单独合成 | 带候选与源片切点的粗剪时间线 | 完整看一遍，故事成立，镜头间关系连贯 |
| 9 声音与字幕精修 | 对白、环境、动作声、音乐、字幕分别处理；按实际语音对时 | 分轨声音、字幕时间线、SRT、混音版 | 说话人准确、对白清楚，静帧段落声音不断裂 |
| 10 画面精修 | 只处理已选片段：超分、调色、稳定、图文安全区、必要局部重做 | 接近交付规格的画面与新版粗剪 | 人物、纹理和动作连续；增强没有引入明显闪烁 |
| 11 交付与复盘 | 输出成片、工程、素材、字幕、许可与版本说明；检查真实使用场景 | 成片包、可编辑项目、制作与费用记录 | 技术检查通过，创作者完整视听验收，接收者能继续使用 |

工作顺序可以局部并行。例如声音基准、角色基准和场景资产可以同步准备；正式对白的时长、口型任务和最终剪辑必须按依赖交接。

## 3. 内容应该怎样分给不同媒体

先问“这段信息让观众怎样获得”，再决定调用哪个模型。

| 信息 | 适合的表现方式 | 本项目中的启发 |
| --- | --- | --- |
| 人物想要什么 | 行动、选择、短台词、反应镜头 | 让人物自己挑红布，比旁白解释她有自主性更有现场感 |
| 系统采取了什么行动 | 可见的动作、界面变化、设备声音 | 按钮要实际按下并收回；“提示成功”不能替代动作 |
| 空间为什么无法通过 | 全景建立尺度＋接触近景＋人物反应 | 台阶、柱口、转向空间要能解释结果 |
| 精确文字、地图、回执 | 本地排版、清晰静帧、可读的停留 | 七个界面无需支付视频生成费，也能避免字形漂移 |
| 人物的情绪与关系 | 声音表演、停顿、视线、细小动作 | 同一句台词的语气与停顿会改变观众对人物关系的理解 |
| 空间与时间连续 | 环境声底、动作声衔接、服装与道具状态 | 切到界面时仍保留该场景环境声 |
| 时间跳转与片尾观点 | 少量字卡、场景变化、音乐与留白 | 单独排版，避免让视频模型生成最终字幕 |

如果题材是广告、知识讲解或纪录片，内容标准会改变：广告需要核对产品卖点，讲解需要事实准确，纪录片需要真实来源。下游生产与交付结构仍可复用。

## 4. 声音要拆成六类资产

| 声音类型 | 设计与制作 | 验收重点 |
| --- | --- | --- |
| 角色对白 | 保存原句、说话人、情绪、语速、停顿与镜内／镜外位置；同一角色用同一声音基准 | 是否串角色、漏字、读错名字、明显换声线 |
| 旁白／讲解 | 先按实际朗读定节奏，再配置支持信息的画面 | 画面与声音是否争抢信息，理解是否来得及 |
| 场景环境声 | 按家中、布店、街道、公园准备连续底声，跨镜保留 | 同一场景是否忽然静音，换场是否有合理变化 |
| 动作音效 | 轮圈接触、布料、按钮、脚步等按动作事件放置 | 事件是否听得到，时间与动作是否对应 |
| 配乐 | 以场景和叙事段落组织，设置进入、退出、交叉淡化和对白避让 | 是否掩盖台词；音乐情绪是否过度解释人物 |
| 静默／呼吸／空间感 | 有意识地保留停顿、呼吸、残响和环境底 | 是否把有意义的沉默误当成需要自动删掉的空白 |

生成模型输出的一条音轨可能已经把人声、动作声和环境声混在一起。把它复制到三个轨道，不能使三种声音独立可编辑；源分离也可能带来伪影。需要精细控制时，应保留独立声音资产，或对无法拆净的段落做有针对性的重制。

### 路线 A：视频与对白同步生成

适合需要人物自然表演、可以接受一定声线变化，或快速试片的任务。本项目最终制作采用这一路线，符合当时用户“优先在视频生成时完成对白”的选择。

操作：

1. 每镜只提供实际说话者的声线、台词、顺序与位置对应。
2. 画面中可见但不说话的人物，只写必要的外观与动作。
3. 画外声单独标明声源，避免把说话者错误生成到画面中。
4. 全片音乐留给后期；逐镜检查模型有没有额外生成音乐、旁白或字幕。
5. 原生对白合用就保留。声音有问题时，先判断能否独立修音；可见口型镜头需要同时检查嘴型。

优点是表演和画面同步生成；代价是独立任务之间的角色声线、读音与对白内容需要反复核对。固定一段“老年女性”描述只能约束方向，不能证明同一声纹。

### 路线 B：先定对白，再组织画面和口型

适合固定角色的连续短剧、配音版本较多、台词经常修改的任务。建议在未来新项目中做对照试验。

1. 按角色选定已授权的声音，逐句生成或录制对白。
2. 记录音频版本与实际时长，用临时画面排好声音节奏。
3. 对需要看清嘴型的镜头，选当前工具支持的音频参考或对口型路径。
4. 对画外对白、手部、背影与听者反应镜头，直接在剪辑阶段承接声音。
5. 用独立环境声与动作声重建现场感，防止更换对白时整个场景突然变空。

后配音本身不会让原视频嘴型自动改变。声音参考与严格口型也不是同一能力。当前模型的音频、首帧、视频编辑等输入模式要逐项核对，不能把参考音频直接塞进旧项目请求。Seedance 官方已说明图像、视频和音频参考及声画编辑能力，但项目仍需专门适配与试片。[Seedance 提示词指南](https://docs.volcengine.com/docs/ark/seedance-2-5-prompt-guide?lang=zh)

### 两条路线怎样结合

同一影片可以按镜头选路线。例如挑布对话保留原生表演；设备声音使用独立固定音色；门外呼喊跨到下一镜；地图段落继续上一场的环境声。混用时仍要维护同一角色的声音基准和整片响度。

## 5. 镜头应该成为最小可追踪单位

一镜至少记录以下信息。它们共同决定生成、修改、剪辑和费用。

| 类别 | 最低需要保存的内容 |
| --- | --- |
| 叙事 | 镜号、场景、这镜让观众看到的变化、上镜与下镜承接 |
| 人物 | 全程可见、中途入画、画外说话的人分别是谁 |
| 状态 | 开始状态 → 核心动作 → 结束状态；衣物、道具、姿态与位置 |
| 画面 | 构图、机位、景别、运镜、光线、首帧／其他参考及其用途 |
| 时间 | 计划成片时长、生成请求时长、实际返回时长、选用区间 |
| 声音 | 台词、角色、声音版本、声音发生时间、环境、音效、配乐策略 |
| 生产 | 工具／供应商、模型与版本、输入模式、提示词版本、候选 ID |
| 质量 | 动作、空间、角色、台词、声音、连续性问题及处理决定 |
| 成本 | 报价、调用单位、实际返回用量、估算费、账单核对状态 |
| 来源 | 素材原件、生成／导入／本地合成、许可记录、选用理由 |

生成时长要给剪辑留合理余量，并服从供应商的最短时长与整数秒要求；不能默认与最终成片时长一致。已经生成的部分被裁掉，通常仍已经产生相应生成成本。

### 第 70 镜说明了为什么要写“谁保持不动”

当前确认的行为是：徐说“转过去，我看看后面。”，**徐留在原处；邱与轮椅转过半圈。**

之前“徐跟着音乐转身”的描述与意图相反。修复时要同时更新动作要求、选用候选、对应声音与字幕，而不能仅在聊天里说一次“改好了”。

对类似镜头，提交给模型的内容应清楚写出：

- 这镜真正发生的动作；
- 动作的起点和终点；
- 哪个人、哪个道具、哪个机位需要保持；
- 本镜实际说话的人及原句；
- 不需要的额外人物、字幕和配乐。

这种约束来自实际失败。它是否能提高新任务通过率，仍需对照样本验证，不能宣称已有某个比例的提升。

## 6. 在关键阶段验收，减少昂贵返工

| 检查时机 | 检查什么 | 发现问题优先改哪里 |
| --- | --- | --- |
| 剧本之后 | 行动能否表达主题、人物是否有选择、台词是否自然 | 剧本与场景设计 |
| 预演之后 | 实际读台词能否容纳、片长、信息密度、动作能否看清 | 分镜、声音节奏与镜头拆分 |
| 参考图之后 | 人数、服装、道具结构、台阶与空间、首尾状态 | 参考资产；不要期待视频替首帧纠错 |
| 代表性试片之后 | 机械接触、说话人、固定外貌与声音方向 | 输入模式、镜头设计、动作描述或工具路线 |
| 单镜完成之后 | 连续动作、人物漂移、台词与声音、可用切片 | 局部剪裁、修音、局部编辑或定向补镜 |
| 全片粗剪之后 | 情节理解、声音跨镜、节奏与连续性 | 时间线、声音与字幕 |
| 最终交付之前 | 完整视听观感、技术规格、工程能否继续编辑 | 对应问题资产与交付包 |

抽帧适合发现外形和关键姿态问题，不能替代连续播放；语音识别适合发现漏字与定位时间，不能替代对表演和口型的试听；文件能解码，不能证明故事讲得好。

字幕应对照实际声音逐句确认。若实际说错了关键台词，需要修声音或显式记录差异；不能只把正确剧本文字盖上去。当前项目已保存字幕对时与识别记录，逐句听感和统一声纹仍有验收边界。

原始通用工作流没有自动固定声纹、自动理解所有角色、自动完成严格对口型的能力。F11 的识别、声音后期与精剪由专用脚本补齐。它们可以成为下一版通用产品的模块，但目前不是一个已全部整合的“一键生成器”。

## 8. 状态、预算与修改怎样贯穿全程

**提交之前**保存提示词、模型、输入资产、预估时长与预算上限；**提交之后**立即保存供应商任务 ID；**完成之后**保存原始文件、媒体信息、实际用量与质量意见。

网络超时需要区分“请求明确未创建”“服务端正在运行”“提交结果不确定”。不确定时先查任务列表和已有 ID，再关联恢复；不能删掉状态重新提交。失败和艺术质量不合格也应分开记录，新的付费候选要有明确目标。

修改时维护依赖：

~~~mermaid
flowchart LR
    A["台词 v2"] --> B["对白音频 v2／实际时长"]
    B --> C["口型相关画面"]
    B --> D["字幕时间"]
    B --> E["声音切点与音乐避让"]
    C --> F["主时间线"]
    D --> F
    E --> F
    F --> G["新交付版本与变更记录"]
~~~

只改音量，通常可以复用画面；改一句台词的长度，可能牵动口型、切点、字幕与后续时间；改整场场景布局，则需要检查多个镜头。下一版系统应该在修改前显示受影响的资产与费用。

## 9. 成片包应当让下一位制作者接得住

至少包括：

1. 可播放成片：字幕版、无对白字幕版及约定的画幅／语言版本。
2. 可编辑工程：画面、声音、字幕分轨，素材自包含。
3. 原始候选与最终选片索引：记录来源、镜号、源片切点与版本。
4. 字幕与文字：SRT／字幕时间线、片尾与图文原件。
5. 声音：独立对白、可用的现场声、环境声、音乐与混音说明。
6. 制作记录：剧本、分镜、提示词、模型版本、用量与任务状态。
7. 交付说明：做了什么、验证到哪里、尚未验证的事项及许可范围记录。
