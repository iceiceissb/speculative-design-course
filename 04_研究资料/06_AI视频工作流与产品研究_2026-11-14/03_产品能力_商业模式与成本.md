## 1. 先把产业链拆开

一个视频项目可能同时向几类公司付费。即使操作都在一个聊天窗口里，这些供给与成本仍然存在。

| 层次 | 用户购买的价值 | 常见计费方式 | 对应产品／本项目实现 |
| --- | --- | --- | --- |
| 通用助手与执行入口 | 理解需求、写作、调用工具、管理长任务 | 订阅、席位、API 用量 | Claude／GPT；Claude Code／Codex 等执行客户端 |
| 基础生成与推理服务 | 图像、视频、语音等模型输出 | 秒、token、张数、字符、预付资源 | Seedance／火山方舟、语音 API |
| 创作应用 | 参考管理、导演控制、模板、画布、生成与审阅 | 会员、积分、功能与并发分层 | 即梦、Higgsfield |
| 后期与交付工具 | 时间线、字幕、混音、调色、工程与格式 | 软件会员、席位、素材与部分功能收费 | 剪映；本地 FFmpeg、识别与超分脚本 |
| 行业工作流与制作服务 | 让品牌、剧集、课程等具体业务按标准交付 | 项目费、软件服务费、团队席位、代制作费 | 我们自己的可产品化方向 |
| 分发与效果 | 让内容触达受众，产生观看、转化或业务价值 | 投放、平台服务、代理服务等 | 本项目尚未建立商业分发链路 |

最后两层是分析框架，不表示已经存在本项目收入。模型调用是供给，素材生成是中间结果，完成客户目的的交付才是业务结果。

## 3. 即梦：以创作场景组织模型能力

**公开事实。** 即梦以图片、视频和创作工具为入口；官网已将短剧、营销与画布等工作方式放到显著位置。开发者在中国区 App Store 的说明中列有会员月度积分、延长视频和去水印等权益。[即梦官网](https://jimeng.jianying.com/ai-tool/home?type=video)、[开发者提供的 App Store 说明](https://apps.apple.com/cn/app/id6503676563)

**商业判断。** 它的价值可以分成三个递进层次：

1. 帮创作者做出单张图或单段视频，完成首次成功。
2. 把人物、场景、分镜和修改连接起来，让创作者持续完成同一个项目。
3. 通过短剧、营销等明确任务提供更直接的交付路径，增加复用和持续付费的理由。

会员与积分把“获得创作能力”和“消耗计算资源”结合起来；高质量、更长时长、特定工具与通道可以形成分层。网站与 App 的价格、促销和权益需分渠道核对，不能用一个最低月费代表整个生产成本。

**可能的优势，属于分析。** 自有模型供给与创作应用结合，有利于更快把能力变成工作方式；中文创作体验和与现有创作工具的协同，也可能降低上手成本。这些优势是否转化为更低成本或更高留存，本次没有经营数据验证。

**主要产品难点。** 用户在意的通常是“我的主角、声音和上一场保持一致，并且改完可以交片”。新增模型和入口本身不足以解决全片一致性、改稿和工程交接问题。

**价格核查边界。** App Store 开发者说明中出现连续包月 69 元、连续包年 659 元。这是本次可读取的渠道说明，不作为即时 Web 完整套餐表或所有用户的实际报价；本次没有登录购买页核对每档积分与模型权益。[对应渠道说明](https://apps.apple.com/cn/app/id6503676563)

## 4. 火山方舟：把模型变成可调用的生产能力

**公开事实与本地证据。** 官方提供视频任务 API 与不同资源购买方式。现有工作流通过真实任务 ID、返回用量与下载素材证明 API 主干已用于本片制作。[Seedance 官方教程](https://docs.volcengine.com/docs/ark/seedance-2-5?lang=zh)、[本地首轮记录](../../00_%E5%BD%93%E5%89%8D%E5%88%9B%E4%BD%9C/12_%E9%A6%96%E8%BD%AEAPI%E8%AF%95%E7%89%87%E4%B8%8E%E6%A3%80%E6%9F%A5_2026-10-18.md)

**商业判断。** 客户包括开发者、制作工具和组织化生产团队。它销售的主要是可编程供给：让程序可批量提交、查询状态、取回结果和核算用量。

按量与资源计划适合不同规模和稳定程度的需求。开发者购买灵活性，同时接手项目状态、审片、素材归档、重试、剪辑与终端体验；API 可用并不等于上层工作流已经完成。

对高价值制作任务，可靠的任务恢复、可核对的计费与稳定的质量，可能比单次最低标价更影响长期选择。服务方的实际推理成本、折扣和利润率没有公开证据，本报告不推算。

**价格边界。** 本片历史计算使用 70 元／百万 completion tokens；这是当时项目记录的费率，不直接当作所有当前任务的统一价格。公开价格页本次打开只提取到页面框架，未完整复核全部价表；新任务应按当前模型、输入类型、输出规格与报价重新计算。[官方价格页](https://docs.volcengine.com/docs/ark/model-pricing?lang=zh&redirect=1)

## 5. Higgsfield：多模型供给之上的创作工作空间

**公开事实。** 官方提供 Cinema Studio、参考与角色相关工具，以及连接 Claude、ChatGPT、CLI 和剪辑软件的路径。官方 API 条款将开发者 API 与消费者订阅分开。[Cinema Studio 指南](https://higgsfield.ai/blog/cinema-studio-4-0-complete-guide)、[集成说明](https://higgsfield.ai/enterprise-help-center/platform/integrations)、[API 条款第 1.2 节](https://open.higgsfield.ai/terms-of-service)

本次模型目录返回 Seedance 的 provider 为 Bytedance，说明平台里的具体生成能力需要按模型看供应商；不能把所有模型都当作 Higgsfield 自研。平台同时经营自身品牌工具，价值也来自统一操作、导演控制、资产和工作流。

### 商业分析：它为什么有机会收取超过裸模型调用的价值

- **减少选型和集成成本。** 用户在一个空间内尝试模型，不必分别维护多套账户、输入方式和素材位置。
- **把专业意图变成操作。** 机位、光线、情绪等控制，使用户更容易表达想拍什么。
- **沉淀角色与资产。** 重复制作同一品牌或角色，会形成持续使用理由。
- **进入现有工作现场。** 助手和剪辑软件集成能减少素材搬运，也增加与创作者已有流程的联系。
- **服务团队治理。** 团队席位、权限、预算和共享资产，对组织比单人试片更有价值。

这些是价值与收入逻辑，不代表已验证的平台毛利。第三方模型成本、重试、存储和高频用户消耗都会影响收益。若平台只剩“统一调用按钮”，上游模型与通用助手都容易替代；项目资产、编辑体验与稳定交付能力更难替代。

## 6. 通用助手、声音与剪辑工具怎么赚钱

### Claude／GPT：创作需求和执行的入口

通用助手可通过订阅、组织席位与 API 使用获得收入；在本流程中，其主要价值是理解创作意图、持续管理上下文和调用专业工具。外部工具开销仍需按服务核对。

从产品竞争看，谁掌握用户的项目状态与工具选择，谁就更有机会成为长期入口。这是战略判断；不代表助手一定能代替专业创作工具。

OpenAI 官方分别提供语音生成、转录等音频工作流。对视频后期中的配音与字幕，可以单独接入相应服务，无需把它们都塞进一次视频生成。[OpenAI 音频工作流](https://developers.openai.com/api/docs/guides/audio)

### 独立声音工具：把“说什么”与“怎样说”变成可修改资产

以 ElevenLabs 为例，官方当前价格页列 Starter 为 6 美元／月、30,000 积分，含 Commercial License；语音、音效、隔离和配音等产品使用共享积分。此处只作为声音服务商业化示例，不建议为本项目重复购买。[ElevenLabs 官方价格页](https://elevenlabs.io/pricing)

商业价值可能来自固定角色、语言版本、逐句改稿和声音工作台，而不只是生成若干秒语音。声音使用权限、可用语言、表演质量和修改成本共同影响选择。

### 剪辑工具：控制最后的交付环节

剪辑工具持有时间线、字幕、混音、素材与输出格式，离最终交付很近。会员、专业功能、素材和团队服务可以形成收入。

本项目已说明：即使视频生成完成，声音衔接、图文、字幕与精剪仍产生大量价值。我们的剪映草稿输出采用社区库适配，不等同于剪映承诺稳定的官方工程 API。

当前 V02 的音乐用于课程短片；未来商用或扩大分发时，需要核对对应曲目的具体范围。能够下载和导出，不代表所有发行用途都已获许可。

## 8. 成本要同时看三本账

**现金账：** 本周期实际支付了多少订阅、充值、积分包与软件费用。充值后未消耗的余额不是这一个项目已经消耗的成本。

**项目消耗账：** 这个项目用了哪些模型、积分、素材和本地计算。把共享订阅按明确规则分摊；同一笔消耗不能先按积分折算，再把整月同一订阅重复加入。

**制作总成本账：** 在资源消耗之外，加上创作、选片、返修、剪辑、沟通和交付时间。比较自动化方案时，应同时观察人工时间和最终质量。

建议计算：

~~~text
项目总成本 =
    视频、图片、声音与LLM的归属消耗
  + 尚未归入上述项目的订阅分摊
  + 素材授权、存储、处理与本地算力
  + 人工创作、修改、审片与交付

有效视频素材成本 = 视频生成消耗 ÷ 最终采用的视频秒数
完整交付成本 = 全部项目成本 ÷ 验收通过的交付数
~~~

含静帧的成片总时长和最终采用的视频秒数是不同分母。记录时要写清，避免把大量静帧带来的低均价当成视频模型本身便宜。

### 一个简单的通过率模型

假设每次生成 8 秒，成功后可用 5 秒，每次满足验收的概率为 p。先忽略候选间相关性和本地修复：

~~~text
每个镜头的期望尝试次数 ≈ 1 / p
生成秒数 / 采用秒数 ≈ 8 / (5 × p)
p=0.5 时，约为 3.2
p=0.25 时，约为 6.4
~~~

这只是解释性模型。真实失败常相关：错误首帧或错误动作要求不变，多抽几次并不一定提高通过率。修输入和拆镜可能比购买更多候选有效。

## 9. 如果把我们的工作流做成产品

先把目标收窄为：**帮助小型制作团队完成多镜头叙事，尤其是角色／声音持续一致和定向改稿。**

可以提供项目与资产管理、候选审片、局部返修、用量账本、声音与字幕依赖、工程导出。先接一个稳定生成路径，避免一开始承担所有供应商的维护。

可尝试的业务结构：

| 模式 | 用户为何付费 | 需要验证的难点 |
| --- | --- | --- |
| 用户自带服务账户／Key，软件收项目或席位费 | 少搬素材、少重复生成、改稿与交付更清楚 | 用户是否愿意配置账户；节约是否可复核 |
| 软件费＋清楚列出的代付生成用量 | 更少的采购与账号操作 | 供应商商业条件、用量结算、失败责任与毛利 |
| 制作服务＋工作流软件 | 客户直接获得可用交付 | 创作与沟通人工可能成为主要成本 |
| 按合格交付收费 | 用户只为结果付费 | 怎样事先定义验收、限制无穷修改、控制生成波动 |

采用代付或集成前要核对相应服务的商业条件。本报告不将普通个人会员视为自动获得二次销售生成服务的权利。

**假设性单位经济示例。** 若一个项目收 199 元，生成消耗 60 元，处理与存储 10 元，支付等 5 元，支持与返修人工 20 元，贡献利润为 104 元，约 52.3%。这里的“贡献利润”扣除列出的可变成本，尚未扣固定研发、管理和获客，不能称为净利润。

若模型尝试量翻倍，生成消耗变为 120 元，其他条件不变，则贡献利润降为 44 元，约 22.1%。价格不变时，局部修复、首帧质量、声音复用和审片效率，直接影响业务能否成立。

本项目还没有付费客户、留存或复购数据。下一阶段要证明的是：相同质量下是否少花钱、少改稿、更快交付，以及团队愿意为多少改善付费。
