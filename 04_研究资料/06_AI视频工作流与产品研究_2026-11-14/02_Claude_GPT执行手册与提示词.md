# 把工作流交给 Claude／GPT：执行手册与提示词

2026-11-14。本手册适用于新项目，也说明怎样继续使用当前本地工程。提示词是工作指令模板；实际执行仍取决于当前客户端连接的工具、文件权限、模型能力和预算。

## 1. 先选一种执行方式

| 方式 | 实际操作 | 适合谁 | 需要承担的成本与限制 |
| --- | --- | --- | --- |
| 对话规划＋人工操作 | Claude／GPT 输出剧本、分镜和提示词；人到即梦／Higgsfield 生成、下载，再导入剪辑软件 | 偶尔制作、先理解流程的人 | 反复复制、命名与回传；仍要单独支付生成服务费用 |
| 对话＋连接工具 | 助手通过官方插件／MCP 查询模型、报价、上传、生成与归档；人审片 | 希望减少跨软件重复操作的个人和小团队 | 需要登录服务并具备对应权益；连接不代表生成免费 |
| 本地执行助手＋API／剪辑脚本 | Claude Code／Codex 等读取项目文件、调用明确的程序，管理候选、时间线和工程输出 | 多镜头长片、持续迭代、需要审计和复用的团队 | 需要配置生成服务凭据或官方连接，维护适配器与编辑格式 |

Higgsfield 官方说明已提供 Claude、ChatGPT 的连接方式，并有 CLI 与剪辑软件集成；Claude 官方也说明了连接器可以读取资料并操作外部服务。不同客户端的操作入口和权限并不完全相同。[Higgsfield 集成说明](https://higgsfield.ai/enterprise-help-center/platform/integrations)、[Claude 连接器说明](https://support.claude.com/en/articles/11176164-use-connectors-to-extend-claude-s-capabilities)

OpenAI 的 API 可以通过 MCP 工具连接外部服务。因此“让 GPT 帮我生成视频”可以由 GPT 理解任务并调用视频服务实现；具体视频能力由被调用工具提供。[OpenAI 官方 MCP 文档](https://developers.openai.com/api/docs/guides/tools-connectors-mcp)

在当前工作区，优先复用本地 T01 工具。当前聊天已有 Higgsfield 工具，本次已成功完成模型目录查询和只读报价；没有试跑该连接的付费生成。无需为了整理这份方案安装新插件。

## 2. 一个项目至少交给助手这些材料

| 材料 | 内容 | 如何避免失去创作意图 |
| --- | --- | --- |
| brief | 受众、核心表达、时长、预算、发布与交付要求 | 把不能接受的改变写清楚 |
| script | 当前完整剧本、版本、台词 | 修订后明确新基线，保留旧版本 |
| references | 人物、道具、服装、场景、风格、声音样本 | 标明每份参考控制什么，哪些镜头可以使用 |
| shot table | 动作起止、人物、对白、声音、剪辑关系 | 全片信息保存在项目中，单镜请求只使用相关内容 |
| assets and state | 现有素材、候选、选片、任务 ID、用量、失败与待定项 | 恢复已有任务；不用重新生成来“查看进度” |
| timeline | 画面与声音切点、字幕、音乐、版本依赖 | 改稿时显示哪些下游资产需要更新 |
| acceptance | 内容、画面、声音、文件和工程的检查标准 | 把技术检查与人的审美验收分别记录 |

仅把文件附在聊天里，不一定已上传给外部视频服务。Higgsfield 官方特别说明：Claude 聊天附件不会自动传入其生成系统，引用素材需要通过相应上传路径确认。[官方文件传递说明](https://higgsfield.ai/enterprise-help-center/platform/integrations)

## 3. 可复制的总控提示词

把下面内容放到项目对话开头，再补齐方括号。它规定产物与协作方式，不预设某一模型永远可用。

~~~text
你协助我把一个视频项目从内容做到可交付成片。

项目目标：
- 题材与核心表达：[填写]
- 受众与播放场景：[填写]
- 成片时长、画幅与语言：[填写]
- 本轮预算上限与已授权范围：[填写；区分订阅、视频、图片、声音]
- 最终交付：[例如字幕版MP4、无对白字幕版、SRT、可编辑工程、素材与说明]
- 工作目录与当前基线：[填写]

请先读取已有的当前稿、分镜、素材、任务状态和修改记录。
列出已经有的材料、缺失材料和当前可用工具，再推进可独立完成的工作。
只对确实影响方向或无法合理推断的信息提问。

工作步骤：
1. 明确创作简报，检查故事、人物行动与台词。
2. 拆成逐镜制作表；同时安排画面、对白、环境、音效、音乐、文字与剪辑关系。
3. 用分镜图和临时声音做低成本预演，核对实际时长。
4. 给每镜选择生成、静帧、本地合成、实拍或现有素材复用。
5. 对关键风险镜头试片，记录问题，确定可行方法后分批生产。
6. 组织候选审片、选用区间、粗剪、声音与字幕精修。
7. 只对已选素材做必要高清与画面修复，输出完整交付包。

持续执行规则：
- 保留已确认的主题、人物、剧情顺序和台词；提出改变时说明理由。
- 每镜只传相关人物与声音；分别处理画内人物、入画人物和画外声音。
- 固定参考、声音、提示词、模型与输入模式的版本；检查当前工具是否支持。
- 持久化候选、任务ID、选片、切点、用量和修改依赖。
- 在已授权的预算与工具规则内推进；超出范围时提供具体变更和费用供我决定。
- 遇到提交结果不确定，先查任务与恢复状态，不盲目重提付费请求。
- 先判断能否剪裁、修音、改静帧或局部编辑，再决定重做整段视频。
- 技术检查、连续播放、声音试听、编辑器内验证分别记录。
- 缺少某种读取或试听能力时标明未验证，不把计划当结果。

每次交接请给出：
当前基线、完成材料、待处理问题、实际费用/估算费用、下一步动作和文件位置。
最终成片必须有可编辑工程和来源记录。
~~~

## 4. 分阶段提示词

### A. 从议题整理为可以拍的故事

~~~text
根据提供的资料和创作意图，整理：
1. 受众、表达目标、核心矛盾和人物想完成的具体事情。
2. 每个角色的目标、阻力、行动、转折与结果。
3. 每场戏里必须让观众看到或听到的信息。
4. 哪些是来源支持的事实，哪些是虚构设定，哪些还待研究。
5. 一版可以在[时长]内完成的剧本。

台词用人物日常会说的话。把观点落实到可见行动和选择。
不要把没有开展的访谈写成研究结论。
保留我的原意；如需要删减场景，列出删减对故事的影响。
~~~

### B. 把剧本拆为多媒体镜头表

~~~text
请按当前剧本输出逐镜表和结构化记录。
每镜包含：
镜号、场景、叙事目的、画幅/景别/机位、完整出镜范围、
动作起点/过程/终点、需保持的状态、台词原句与说话人、
画内/画外声音、环境声、动作音效、音乐策略、图文、
计划成片时长、生成请求时长、首帧/其他参考、承接关系、
制作方法、风险、验收标准。

复杂的抓握、接触、越阶和多人调度，先判断是否需要拆镜。
精确文字与界面优先本地制作。
用实际读台词的时间校正镜头时长。
每镜说明为什么需要这一镜；给出全片累计时间。
~~~

### C. 生成某一镜头的提交材料

~~~text
为镜头[镜号]编制提交材料，参考当前选定工具的模型说明与输入限制。

先核对：
- 参考图中实际出现谁，完整镜头中谁会入画或出画；
- 谁说话，谁仅在画面中，谁在画外；
- 本镜哪些资产应保持，哪些发生变化；
- 选择首帧、首尾帧、参考生成、动作参考还是视频编辑；
- 时长、分辨率、画幅和音频参数是否受当前模式限制。

输出：
1. 人能审阅的镜头意图与状态变化。
2. 参考资产清单及每份参考的用途。
3. 给视频模型的精简提示词，只写本镜相关信息。
4. 台词、说话人映射与声音策略。
5. 报价、目标候选数、可用区间预期与验收项目。

保留台词原句，不附全剧人物表。
还未获得当前模型参数时，先列待核对项，不发明参数名。
~~~

### D. 声音制作与统一

~~~text
为这部片建立声音表，区分角色对白、旁白、环境声、动作声、配乐和有意的静默。

按镜头判断：
- 保留原生对白，还是先做独立对白再组织画面；
- 哪些需要清晰口型，哪些可以画外、背影或反应镜头承接；
- 同一角色使用的声音基准、情绪、语速和停顿；
- 本镜和下一镜声音如何相接。

保存每句台词的ID、说话人、文本版本、音频版本、实际时长与时间线位置。
固定声线的文字描述只能约束方向，不当作声纹一致性的证明。
如果原视频是一条混合音轨，说明如何处理旧人声与原有环境声。
先核对已有会员和现有工具，不重复购买声音服务。
~~~

当前影片延续当时选择的原生对白路线。对新项目可比较独立配音路线的修改成本，不能据此擅自重做现有成片。

### E. 审片与局部返修

~~~text
检查这些候选，按技术可用、叙事动作、角色一致性、台词、
声音、口型和跨镜连续性分别记录。

对每个问题给出：
镜号/候选、可复核的时间点、实际看到或听到什么、
与预期的差异、严重程度、是否有可用切片、修复方案与费用影响。

修复顺序根据问题选择：
复用或改切点 → 本地声音/图文修复 → 局部视频编辑 → 定向补镜。
需要改分镜才能讲清楚时，说明新的镜头设计。

不得把API成功当作艺术验收通过。
没有连续播放或试听的内容明确标记。
遇到明确拒绝不重提相同输入，先采用符合服务规则的其他制作方法。
~~~

### F. 剪辑与交付

~~~text
根据已选候选创建可编辑时间线，并输出完整成片。

时间线保存源片、源片起点、使用时长、成片位置和镜号。
对白与现场声、连续环境声、动作音效、配乐和字幕尽量分别成轨。
音乐按场景连续组织，对白处避让；按实际声音对齐字幕。
静态界面保留清晰文字和足够阅读时间。

只对已选片段进行必要超分与画面修复。
输出字幕版、无对白字幕版、SRT、工程、素材和交付说明。
检查尺寸、帧率、时长、音轨、全片解码、字幕边界、工程路径和来源。
完整播放试听与编辑器内打开/导出另行记录。
如果编辑器原生导出未验证，应明确成片实际使用的编码路径。
~~~

### 只检查通用工具的依赖和根项目计划

~~~powershell
Set-Location -LiteralPath 'D:\课\大四上\思辨设计\06_制作工具\T01_AI视频工作流'
python -X utf8 workflow.py doctor
python -X utf8 workflow.py plan
~~~

这两条用于依赖检查和计划查看，不提交视频生成。**根目录的 plan 对应根 project.json，不能当作 F11 全片计划。**

本次实际运行 doctor：Python 3.13.5、FFmpeg、FFprobe 可用，根项目参考图片无缺失；返回 4 个任务、20 秒时间线，进一步确认它是旧演示入口。该检查不证明当前云端账户、模型权限或生成质量。

当前通用 CLI 没有全局 --project 参数。底层有 Workflow(项目目录) 的 Python 接口，F11 专用脚本用它选择子项目。因此新项目需要先准备兼容配置和明确入口；不能凭空在命令行补一个未实现的参数。

### 已有素材导入与粗剪

工具提供 import、select、assemble --kind both。它们作用于当前入口选定的项目；示例命令见 [本地 README](../../06_%E5%88%B6%E4%BD%9C%E5%B7%A5%E5%85%B7/T01_AI%E8%A7%86%E9%A2%91%E5%B7%A5%E4%BD%9C%E6%B5%81/README_%E5%85%88%E7%9C%8B%E8%BF%99%E9%87%8C.md)。

普通 assemble 负责通用粗剪；F11 的完整声音与字幕精修使用专用编辑脚本。不能用普通 assemble 覆盖已经修好的 V02 作为新版成片。

### 新的付费生产

先生成计划和报价，核对模型、输入模式、参考、候选数和调用上限。在用户现有授权范围及所用工具的规则内执行。预算不足或要改变分配时，提供具体镜头与费用影响。

当前本地状态恢复逻辑、Higgsfield 的工具报价、即梦的网页权益分别管理，不能混成一个余额。密钥只进入本地配置或相应服务的认证入口。

## 6. 如果换成 Higgsfield 或即梦

### Higgsfield 路线

1. 在目标助手中连接 Higgsfield 账户，查询当前可用模型与参数。
2. 上传已选参考并确认素材可用，建立角色、道具和场景引用。
3. 对同一镜头的固定规格先获取报价，再在已授权范围内生成。
4. 保存真实任务状态、候选与选用决定；成功素材下载回本地项目。
5. 延续同一套镜头表和时间线进行后期，或使用已验证的编辑器集成。

本次 MCP 只读报价：Seedance 2.5、5 秒、16:9、有声，720p 为 35 积分，1080p 为 80 积分。报价未创建生成任务；不构成任何免费或 Unlimited 权益的验证。

### 即梦路线

即梦官网已经展示短剧工作室、画布、局部重拍、Agent 插件／CLI 入口。对于手动制作，可以先在即梦生成和筛选，再把下载文件按镜号导入本地；如果希望通过官方插件自动制作，需要另外核对安装、登录、支持的调用和计费范围。[即梦官网](https://jimeng.jianying.com/ai-tool/home?type=video)

本地现有“即梦导入”能力指导入视频文件。现有自动付费提交走火山方舟 API，**不能把它描述为已实现即梦客户端自动操作**。

## 7. 下一版通用工具需要补哪些能力

| 改造 | 为什么有必要 | 当前状态 |
| --- | --- | --- |
| 显式项目选择与预览 | 避免根目录旧演示与当前影片混淆 | 通用 CLI 尚未提供项目参数 |
| 供应商适配器 | 同一镜头表调用不同模型，同时校验不同输入规则 | 现有主干为 Seedance；Higgsfield 接入未与本地状态统一 |
| 角色／声音资产版本 | 长片中统一外貌、声音与表演参考 | 已有文字设定和图像资产；声音未统一成完整资产管理 |
| 统一预算账本 | 区分元、美元、积分、报价、实际用量和最终账单 | 已有局部记录，尚非跨供应商总账 |
| 修改依赖追踪 | 改台词或动作时自动提示受影响镜头、字幕与时间线 | 目前主要依赖专用脚本和制作判断 |
| 审片意见结构化 | 把“动作不对”定位到人物、时间点和目标变化 | 已有人工检查与抽帧，尚非通用审片产品 |
| 真正可接续的工程验证 | 接收者能在剪辑软件继续修改并导出 | 已验证文件与草稿结构，原生剪映打开／导出仍待补 |

以上是产品化待办，不是本次已经完成的功能。
