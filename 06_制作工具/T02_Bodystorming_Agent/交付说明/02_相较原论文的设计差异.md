# 相较原论文的设计差异

比较对象：用户提供的《Bodystorming through Disruption: AI-assisted Design Improvisation Pedagogy》，重点为 §3.1.2 AI System Design、§3.2 Workshop Process 与 §3.2.2 Embodied Improvisational Enactment。

本文比较论文公开描述与本原型的机制。没有原作者源码或完整系统配置，不能把“文中没有详细说明”写成“原系统必然没有”。也不能把程序实现直接写成经过验证的研究贡献。

## 1. 沿用的基础

| 内容 | 论文描述 | 本原型的关系 |
|---|---|---|
| AI 定位 | 作为表演圈外的 Out-Actor 提供扰动，保留学生的解释和行动权 | 沿用；不是本原型提出的新定位 |
| 基本链路 | 初始情境、剧情提炼、检索、五个突发事件、表演支持 | 沿用基本任务链；本地程序实现具体节点 |
| 人工选择 | 表演组选择事件，转化成身体行动，可继续询问或调整表演 | 沿用；不能把“人在回路”整体当成新增机制 |
| 课堂分工 | 观察组操作 AI、表演组行动，教师组织、调节难度并引导反思 | 沿用分工；“老师课前准备”的页面是本原型的组织方式 |
| 观察与反馈 | 观察组使用结构化观察表、口头反馈与同伴评价，轮换角色 | 论文已有；本原型尝试将部分提示过程记录到系统中 |
| 身体表达空间 | 提供结构化、客观的知识支持，身体解释留给学生 | 沿用其教学意图；进一步尝试不同程度的提示 |

## 2. 机制层面的延展

| 维度 | 论文公开描述 | 本原型的进一步设计 | 已实现到什么程度 |
|---|---|---|---|
| 现实条件 | 以初始情境和剧情摘要进入系统，讨论建议的实践可行性和教学适用性；没有详细给出现场资源的结构化输入格式 | 将材料、空间、人数、时长、规则与学习重点独立保存，在每次引导时继续约束建议 | 勾选配置、自动条件单、后端统一生成约束、进入事件与引导节点；尚不能自动证明每条建议符合所有条件 |
| 现场观察如何进入引导 | 有观察表、实时记录和反馈，但未详细给出它们怎样作为每轮 Agent 状态或输入 | 将可观察动作、对话与“需要怎样的支持”分开输入，保留不确定状态 | 快捷观察、可选补充、明确支持请求；仍由人确认，没有自动识别停滞 |
| 介入程度 | 支持模块提供知识与结构化建议，教师校准难度；未详细给出每轮支持的分级策略 | 显式设置 L0（继续探索）、待确认、L1（问题）、L2（方向）和 L3（短小动作起点） | 规则选择级别；L0/待确认在真实模式不调用模型，其余按级别组织提示。此分级是本原型的设计，不是论文的原有分级 |
| 信息呈现时机 | AI 输出向所有组展示并讨论，学生选择和解释；未细化每条支持的发布状态 | 将生成、人工确认、向学生展示分开，支持暂时留白和替换已展示内容 | 独立投屏、人工发布、已发布内容快照；继续生成不会自动覆盖学生看到的提示 |
| 提示如何被使用 | 有反复询问、口头反馈、同伴评价与反思；未详细报告逐条提示状态如何影响后续生成 | 区分未展示、已告知、采纳/修改、拒绝；未展示的内容不视为学生已经获得的支持 | 状态持久化、选中事件与提示历史进入后续引导、拒绝记录、未展示不触发支持升级。尚不包含对学生具体改造动作的自动记录 |
| 可核查的过程 | 文中描述节点、检索和调试过程，但没有展开逐轮输入输出的查看与导出界面 | 将每次模型/规则节点输入、输出、错误、级别和展示记录保留，供方法讨论与反思 | 工作流提示词查看、节点日志、Markdown / JSON 导出；记录不等同于事实验证或学习效果评价 |

本原型的 L0–L3 是“支持强度分级”。论文 §3.2.2 提到的四层渐进式课堂结构属于工作坊流程，不能与本原型的支持等级混为一谈。

## 3. 为课堂操作补上的产品交互

任务起点、材料勾选、可复用方案、快捷观察与独立投屏，降低的是课堂操作成本。它们帮助上述机制可见、可操作，但单独看并不足以构成论文创新。

可以形成的研究问题是：**具身设计即兴中，AI 应依据哪些现场信息介入、由谁确认介入，以及学生怎样拒绝或改造支持？**

可以围绕“现实条件—观察解释—介入决策—学生使用”讨论设计框架，并用典型情境和反例推演论证。例如：沉默但持续调整道具；讨论热烈却反复重复方案；系统已生成提示但学生尚未看到。三者说明“感知到一个信号”与“应该立即帮助”之间还存在解释与决定的环节。

## 4. 与原论文能力不等价的部分

- 论文在 Coze 上结合 Workflow、ChatFlow、理论节点与 BingWebResearch。本原型用本地 Python/React 实现，检索为本地词法检索，**没有复现联网学术检索和所谓双层验证**。
- 原文关于科学准确性的表述属于作者对其系统的描述。本原型只检查字段、事件数量、级别与引用 ID，不能据此保证事实正确或科学适用。
- 演示模式是固定手写数据，验证操作流程；真实生成需配置自己的兼容模型 API。尚未以真实课堂或模型输出质量评价验证这些设计。
- 照片分析需要外部视觉模型，结果经人确认；语音当前是已有转写文本。实时视觉、语音和传感器融合是后续设想，不能写成已完成能力。
- 当前单机、单活动，没有多人账号权限、多设备扫码或多组同步。

## 5. 对外描述的准确说法

“参照论文做了一个可交互原型，在其场外 AI 思路上，进一步细化现场条件、介入强度、提示展示和学生反馈的机制，准备讨论这些设计能否形成后续研究问题。”

不宜称为“已证明优于原论文的系统”“完整复现原作者 Agent”，也不宜把原论文已有的观察组操作、检索或五个事件当成本原型新增贡献。
