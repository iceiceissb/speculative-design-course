# 给学姐的介绍

学姐，我参照你发的那篇论文，先搭了一个可以本地运行的 Bodystorming 工作台，保留了“生成五个扰动—学生选择—提供表演支持”的基本思路，想先用可交互的形式讨论 Agent 可以怎样进一步设计。

相较论文中描述的机制，我主要尝试细化了三个方面：

1. **让 Agent 明确现场条件**：把真实材料、空间、人数、时长和规则单独配置，传给事件生成和后续引导，区分故事中的设备与教室里实际可用的东西。
2. **把是否介入也纳入决策**：根据观察和学生的支持需求，提供不同程度的帮助；正在自主探索时可以不追加提示，不确定时先询问，不把沉默直接当成卡住。
3. **区分生成、展示和使用**：提示先由操作端预览，人确认后才展示给表演组，再记录学生是否采纳、修改或拒绝，后续支持参考这些记录。

观察组操作、表演组选择扰动、老师组织和引导反思，这些分工是沿用论文的；材料勾选、方案复用和独立投屏，是为了让上述机制更方便在课堂里操作。

你之前提到的视觉、语音，我想可以作为现场观察的来源，再进一步讨论：感知结果能说明什么、谁来确认，以及什么情况下才适合打断或给提示。目前有照片分析接口和转写文本入口，还没有接实时传感器。

现在主要可以用演示模式体验流程，真实生成还需要配置模型 API。包里放了启动说明、界面截图和与原论文的对照，你可以先看看这些延展是否值得作为后续论文讨论的方向。
