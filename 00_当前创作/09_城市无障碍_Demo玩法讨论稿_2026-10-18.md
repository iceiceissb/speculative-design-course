# 《不用麻烦她》：城市无障碍 Demo 玩法讨论稿

2026-10-18｜基于 S35 v9｜玩法建议，待讨论｜尚未制作可运行原型。

本轮用户提出：体验者扮演坐智能轮椅的人，沿途遇到无障碍不友好的地方时，可以报备给政府，推动维修。本稿完善体验目标、互动方式与城市反馈，不改写剧本。

剧本基线：[S35《不用麻烦她》v9](../01_%E5%89%A7%E6%9C%AC%E7%89%88%E6%9C%AC/04_%E4%B8%A4%E4%BD%8D%E8%80%81%E5%8F%8B/S35_%E4%B8%8D%E7%94%A8%E9%BA%BB%E7%83%A6%E5%A5%B9_v9/%E4%B8%8D%E7%94%A8%E9%BA%BB%E7%83%A6%E5%A5%B9_v9_%E5%AE%8C%E6%95%B4%E5%89%A7%E6%9C%AC.md)。

## 1. 体验者是谁，出门要做什么

玩家扮演邱懿贞，坐着秀秀，带上徐月禾的舞裙，去青禾布店配扣子、给自己挑红布。之后两人约在公园见面。

日常目标把街区串起来。玩家决定今天怎样走、哪些事情先做；报障、查看处理进展和参与试用，发生在日常出行途中。徐的接孩子安排通过简短对话保留，不用倒计时逼迫玩家放弃报障。

推荐一条约 8—10 分钟的体验主线，时间为设计估计，需在纸面走查和原型试用中调整。采用一条可探索的小街：家—西街柱口—青禾布店—公园。体验跨越当天、数周后、数月后的回访，以明确时间字幕切换。

## 2. 核心循环

出门办事 → 在现场观察障碍 → 决定当下怎样通行 → 确认或暂存问题记录 → 继续自己的行程 → 收到处理消息 → 回到原处试用 → 更新路况或提出调整。

两类结果始终独立：

- **这次怎样过去了：** 使用秀秀的越障能力、绕行、等待清理，或暂时改变目的地。
- **现场现在是什么情况：** 柱口仍窄、入口仍有台阶、坡道暂时被占，或已完成改造并留下试用记录。

使用越障能力后，现场的问题记录仍然成立。玩家可以先完成自己的事，在返程或到家后整理提交，不必在每个地点反复填表。

## 3. 玩家实际操作什么

推荐坐姿附近的视角，画面下方保留扶手和控制器，角落放一张简明街区图。普通移动使用方向键或屏幕摇杆；到达障碍附近才出现情境操作。

| 操作 | 玩家做的事 | 可见反馈 |
| --- | --- | --- |
| 观察 | 转动视角，查看入口、侧坡和周围绕行空间 | 轮椅停在障碍前，显示现场事实，不直接替玩家判定全部情况 |
| 通行 | 选择使用秀秀、绕行或稍后再来 | 行程改变；越障采用确认后的预设动作，避免把体验做成操控技巧考试 |
| 留下记录 | 选一个拍摄位置，在照片上点出挡住通路的位置 | 秀秀生成含位置、照片、时间的草稿 |
| 核对并提交 | 查看草稿，改正遗漏，选择现在提交或先存下 | 获得模拟回执；地图显示现场状况和反馈状态 |
| 回访 | 再次走同一段路，查看施工变化，参与试用 | 看见修复效果；仍有问题时可直接补充到原记录 |

报障控制在一张卡片内完成。例如：

> 青禾布店入口：两级台阶；侧面有坡，普通轮椅使用者反馈无法独立上行。秀秀本次使用越阶机构进入。
>
> [查看照片] [修改描述] [先存下] [确认提交]

自动生成的描述允许编辑。测量尚未完成时写“待现场测量”，不生成虚假的精确坡度或合规结论。

## 4. 三个地点，三种不同玩法

### 西街柱口：自己能过，问题仍然保留

玩家抵达柱口，尝试普通模式时停下。可以确认使用秀秀的收拢机构通过，也可以选择地图上的绕行路。收拢后仍需保留乘坐者、扶手和底盘真实所需的空间。

通过时提示“本次使用收拢机构”。后续学会纠正共享规则后，玩家可回看这个地点，给柱间障碍补上记录。提交后原处仍保留两根柱子；数月后的回访才看见重新布置后的通道。

绕行有可见的路线差异，保持短距离，不要求玩家体验漫长重复的受阻过程。

### 青禾布店：修正错误共享，再检验改造

这是整段 Demo 的重点，保留 v9 的两次转折。

第一次到店时，玩家确认使用越阶机构，进入店里挑扣子和红布。扶手屏幕短暂出现“本次通行完成”，共享地图将入口误标为绿色。这是开场的既有错误规则，画面应交代清楚，不能把自动错误算成玩家主动误报。

来客随后到达，展示“轮椅可通行”的导航，却被台阶挡住。她自己提出：“这坡我上不了。”

玩家返回门口，打开刚才的通行记录，补上台阶与侧坡的信息，把记录改为“秀秀使用越阶机构通过”。更正路况后，可另行确认把问题交给街道。**信息更正立即影响导航提示；工程改造进入后续处理。**

后续地点中，系统沿用修正后的记录方式，玩家能直接看见秀秀怎样改变下一次共享。

数月后回访，门口已经有新坡道。玩家沿坡道上去，越阶机构保持收起。来客也参与试用，坡道顶部却容不下她的转弯动作。

玩家可以切到她的坐姿视角，缓慢尝试转入店门；到脚踏接近边沿时停下，不出现碰撞伤害或反复失败惩罚。随后在现场照片上点出转弯空间不足，把问题补充到原工单。

状态保持“待试用／需调整”。下一次回访，平台加宽、店主移走门边货架，来客能够自行转弯进店。试用记录回到地图上。

### 公园坡道：有人占用时，通行状态会变化

坡道本身存在，但入口停着电动车。玩家可留下一张照片，选择临时可用的另一条入口继续赴约。

记录注明“通道被占用”，附时间；模拟街道联系现场管理方清理。清理后的回访照片更新当前状态，历史记录保留。它和柱口、布店的工程改造呈现不同处理路径。

这是支线地点。最小版本可以先省略，优先把柱口和布店的闭环做完整。

## 5. 城市系统怎样真正进入玩法

### 看得见谁在接续处理

提交后先得到“已接收，待核查”。后续分为现场核查、协调场所与设计、施工、试用和回访。街道工作人员、店主、设计人员、使用者分别留下具体动作或回复。

推荐工单状态：

`已接收 → 待核查 → 方案协调 → 施工中 → 待试用 → 已完成本轮核查`

试用发现问题时：

`待试用 → 需调整 → 调整中 → 再次试用`

暂未推进时给出当前原因及下一步，如“待确认门前平台方案”，允许补充和查询，避免只有一个永久不变的“处理中”。

这些是近未来 Demo 的模拟流程，具体名称和职责为体验设定。首版在本地演示，不接入真实政府系统。

### 从一个地点，看到一段生活路线

数周后的街区图上，出现其他居民的反馈：普通轮椅使用者的纸质意见、工作人员走访记录、公交站附近的断点照片。

工作人员在图上把西街柱口、布店、公园和公交站连起来，说明这次计划打通的连续路线。玩家可以查看哪些断点仍会让一段行程中断。

同一地点的多次反映合并进一个工单，保留不同人的描述。居民重复报送会补充证据，不用“刷次数”获得积分或维修优先权。报送少的地方仍可通过纸质意见、走访和主动核查进入视野。

玩家保持居民身份，参加讨论和试用；首版不增加政府经营界面或让玩家独自决定全城预算。

### 地图始终保留具体条件

地图把“入口现状”与“反馈处理进度”分别呈现。提交工单、设备通过、完成施工，都不会单独清除障碍标记。

改造并试用后，可以显示“已核查可通行”，同时保留现场照片、核查日期、参与试用的轮椅类型和已知条件。绿色标记的含义限于已有核查记录，避免再次把一次通过扩展成所有人的通行保证。

## 6. 一次完整体验的节奏

| 阶段 | 体验内容 | 预计时间 |
| --- | --- | --- |
| 出门 | 带上舞裙，看到徐的约定，学习移动 | 约 30 秒 |
| 柱口 | 尝试普通通行，选择收拢或绕行 | 约 1 分钟 |
| 布店 | 越阶进店、挑选、遇见来客，修正共享并提交 | 约 2—3 分钟 |
| 继续生活 | 去公园，选做占道支线；与徐短暂相见 | 约 1 分钟 |
| 数周后 | 查看街区汇聚的反馈与连通路线方案 | 约 1 分钟 |
| 数月后 | 同路回访，发现转弯问题并补充；再次试用 | 约 2 分钟 |
| 结束 | 来客进入布店，邱与徐再次在公园相聚 | 约 30 秒 |

结束页展示本次行程的具体变化：哪些地方借助秀秀通过，哪些环境仍待处理，哪些已经留下改造后的试用记录。不显示道德分数或报障排行榜。

## 7. 选择怎样产生后果

- **先办事，后提交：** 草稿一直保留，返程时可集中核对。生活任务正常继续。
- **暂不提交：** 个人记录保留，已更正的事实继续用于路况提示；没有提交的草稿不虚构成已进入街道办理。其他居民的反馈仍可能推动同一地点的处理。
- **使用秀秀通过：** 越障能力真实有效，玩家正常到达目的地；现场障碍继续记录。
- **补充遗漏：** 新事实挂回同一地点和工单，旧版本可查看，不生成互相矛盾的独立结论。
- **改造后仍无法转弯：** 试用结果触发继续调整；完成一次施工不会自动宣布结束。

主线可用布店的一个引导案例演示完整流程，其余地点开放选择。玩家不承担巡查全城或保证所有问题获修的责任。

## 8. 首版制作范围与现有工具

建议先完成柱口、布店两个地点和三种场景状态：改造前、第一轮施工后、调整后。同一条路复用场景资产，重点制作轮椅动作、共享信息更正和入口转弯试用。

现有 D07 使用本地 Three.js，已经有轮椅人物、3D 场景、情境选择和跨幕状态记录，可作为资产与部分交互代码的来源。当前代码按旧故事演示动作；玩家角色、自由移动、碰撞边界、工单状态和新街区需要重新实现，不能直接把旧六幕换文案视为完成。

制作时另建后续 D 版本，保留 D07 历史快照。首版使用本地预设的事件与工单进度，无需账号或付费生成额度；其他居民的记录明确标为演示内容。

开始写代码前，可使用已有 T02 Bodystorming Agent 的演示模式，配合纸面地图走一遍“已通过但别人进不来”“修后仍转不过弯”两个事件。该模式使用固定样例，需要人工输入这次情境与观察；无需模型额度。它能帮助发现提示是否过早、玩家是否看懂因果，再确定界面与场景制作。真实模型模式需要服务商密钥与相应额度，本轮无需启用。

## 9. 纸面走查要验证的事

1. 体验者能否说清自己今天想去哪里、要做什么。
2. 看到来客受阻后，能否从刚才的共享记录找到问题，并理解为什么要更正。
3. 能否辨认已提交、已施工、已试用三个不同状态。
4. 在布店试用时，是否看见转弯空间的问题，而非只盯着坡面。
5. 结束时能否指出同一路线上实际改变的地方，以及仍需跟进的地点。

待讨论的主要选择：首版是否保留公园占道支线；城市变化采用数月跨度还是与 v9 一样延伸到两年后的结尾。这两项不影响先验证布店主线。
