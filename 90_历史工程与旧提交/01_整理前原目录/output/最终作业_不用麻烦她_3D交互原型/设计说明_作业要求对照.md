# 不用麻烦她 设计说明与作业要求对照

## 机器人与具体情境

秀秀是一台服务邱懿贞的虚构智能轮椅。它能独自导航、避障、承重、辅助推行和监测风险。故事里的冲突发生在高频日常：小区缓坡、早市买菜、晚上邀请老朋友。它要处理的不是单一效率任务，而是邱懿贞与徐月禾有来有往的关系。

观众扮演秀秀。六幕都采用“先行动—观察人的反应—再回应”的两步结构。选择依次影响：两人能否说完话；邱懿贞能否用经验挑菜、回报朋友；她能否亲自邀请徐月禾；徐月禾为何而来；她是否知道轮椅在坡上提供了多少帮助；秀秀是否在下一次真的执行反馈。路口、早市、坡道、下一次及坡道反馈回应设有限时选择；超时执行事先明示的默认动作，后果照常进入剧情。原型持续显示可观察的关系事实，最后自动形成按本次选择变化的行动规则，并将坡道反馈与下一次实际动作并列核对；六幕完整行动记录可展开查看，不计算道德分数。

## 可观察的修养能力

| 修养要求 | 在原型里发生什么 |
| --- | --- |
| 尊重意愿 | 秀秀可以停下来等两人说完、提示价格后让邱懿贞挑菜；邀请必须由邱懿贞亲自发出。 |
| 承认局限 | 自检只能证明设备正常，不能把“想见朋友”诊断为故障；秀秀需要询问真正需求。 |
| 合理拒绝 | 观众可以拒绝自动购买；秀秀也可以拒绝代发带有故障借口的私聊。 |
| 纠正错误 | 抢先买错菜可询问换菜；用故障借口邀约可补发澄清；见面误解可得到当事人同意后修复；坡道反馈可在下一次实际执行或再次忽略。 |
| 安全底线 | 即使关闭预防性助力，侧翻、跌倒或突发不适时也立即接管。安全保护不作为可取消的选项。 |

## 设计依据与取舍

前期先建立机器人自我修养主库：截至 2026-09-18 有 268 条去重记录。轮椅专题从主库目的性选取 14 条种子，补充来源归并为 8 个新候选，共 22 个候选、12 例纳入，并分为共享行动、承认局限、身体与信息边界、接受纠正四类；这不是对 268 条材料的全量系统综述。方法包括 PCC 范围界定、探索性检索与来源去重、区分真实研究/设计作品/虚构叙事、标注证据边界，再把案例事实、价值解释与设计动作分开推理。下列三个最终故事参照在主库中分别编号 RC045、RC060、RC059；其中 RC060 同时是轮椅专题 W09，另外两项来自更大的主库。

1. **RC045：**[Superflux《Uninvited Guests》](https://superflux.in/index.php/work/uninvited-guests/) 用批判性未来情境呈现智能照护物件与老年人日常习惯之间的摩擦。本作品借用了“便利改变生活仪式”的提问方式，转到两个朋友共同完成日常小事的关系。它不证明现实中的智能轮椅一定会造成关系疏远。
2. **RC060：**[Dietrich 等人关于社交机器人披露行为的研究](https://www.frontiersin.org/journals/robotics-and-ai/articles/10.3389/frobt.2023.1236733/full) 讨论机器人在帮助主人与第三者协作时，何种个人信息披露可能被认为合适。本作品把这个问题转译为“设备正常｜希望同伴同行”必须经邱懿贞确认，以及坡道助力是否应告知徐月禾。原型没有实现真实的隐私判断算法。
3. **RC059：**[Anderson 等人的价值驱动老年照护机器人研究](https://proceedingsoftheieee.ieee.org/a-value-driven-eldercare-robot-virtual-and-physical-instantiations-of-a-case-supported-principle-based-behavior-paradigm/) 探索在照护场景中用明确原则解释机器人的伦理相关行为。本作品将“设备状态如实”“让主人亲自表态”“安全风险立即接管”写成观众可检视和修改的规则。影片与原型中的秀秀能力为设计虚构，不能等同于论文中的实物系统。

## 交互与 AI 工具

轮椅选题由作者此前的轮椅项目联想而来；人物关系、冲突、剧本和台词有多轮人工构思、筛选与修改。GPT 参与资料整理、文案、PPT、交互原型与测试脚本制作。原型使用本地附带的 **Three.js r128** 在浏览器实时渲染三维场景，角色与市场、室内、缓坡由代码模型搭建；ImageGen 生成界面概念、角色设定图及分镜参考帧。角色图片作为设定图展示，三维体验使用可旋转的程序化模型，没有把图片冒充三维资产。即梦用于生成视频片段。

原型在本机 Chrome 逐幕截图，遍历 48 个主行动与回应动作的关键时间点，并检查沿路角色坐标、推行方向与可通行区域；坐姿及室内储物柜位置已复核。本轮还核对了“暗中补力 → 收到反馈 → 下一次采纳”及“收到反馈 → 下一次忽略”的对照流程：下一次选项随规则变化，明确求助前 3D 助力灯关闭、求助后亮起；结尾自动生成相应规则，手机页面没有横向溢出。36 张分镜参考帧由 ImageGen 依据已确认的角色设定图生成或沿用上一版。按 36 个 5 秒画面单位组织的网页见 [即梦视频制作台](%E5%88%86%E9%95%9C%E5%9B%BE/30%E5%B8%A7%E5%88%B6%E4%BD%9C%E7%89%88/%E5%8D%B3%E6%A2%A6%E5%88%B6%E4%BD%9C%E5%8F%B0.html)，交互分支见 [Demo 逻辑说明](Demo_%E4%BA%A4%E4%BA%92%E9%80%BB%E8%BE%91%E8%AF%B4%E6%98%8E.md)。视频画面表达设计设想；剧本和交互分支是预设脚本；实际实现的是离线浏览器中的选择、反馈和 3D 动作，没有真实轮椅控制、物理风险检测或自主学习。
